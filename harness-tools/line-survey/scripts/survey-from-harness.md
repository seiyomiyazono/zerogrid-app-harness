# 商品フォルダから survey.json を作る（2026-10-20）

**2026-10-20 運営者 の新しい向き（こちらが先）**：「LINE はハーネスとの連携を強めて的確に。『立ち仕事で悩んでいませんか？』ではなく『本当にあなたに合うのか？』を再度確かめるのが LINE。悩みは VSL・記事・PDP で散々言っているので、LINE は最後の最後の不安だけ。それでクーポンを渡す。」
→ 新しい商品は **相性チェック（`mode: "fit_check"`）** で作る。下の「相性チェック」が手順。今までの「診断」（悩みを聞く・今の対策・比べる）は元の店の本番の形として残し、新しくは作らない。

## 相性チェック（mode: fit_check）

流れ：友だち追加 → 相性の問い 3〜5（使う場所・体格／サイズ・足元・置く所など）→（入力中…）→「あなたに合います（あなたの答えから理由3つ）」＋最後の不安のカード ／ A の「使えない人」に当たる答えがあれば、正直に「合わないかもしれません」（「それでも答えを見る」「今回はやめておく」）→ 不安ごとの答えのカード（何度でも）→ クーポン（回答のお礼・1,000円・24時間・1人1回）→ おすすめ（身長などサイズの答えでバリアントを先に選ぶ）→ 購入手続きへ直行。仕組み（返事は reply だけ・答えは postback に持ち回る・人ごとの割引・カート・LIFF）は元の店と同じ。

### 作る道具（機械の部分は毎回同じ結果）
```
node scripts/fitcheck-from-harness.mjs <newec_harness/<商品>> --out products/<id>-fitcheck/survey.json --base <前の survey.json> --id <id> [--llm auto|on|off] [--pack <出典の束.json>]
node scripts/check.mjs products/<id>-fitcheck/survey.json
python3 images/make_images.py products/<id>-fitcheck/survey.json <gen> products/<id>-fitcheck/img --only fit_ok,d_d1,coupon,hero,richmenu
```
- 機械：出典を探して行番号つきで `_sources` に残す → 問い → 不安 → 答え → 店・値段・色。言葉：`claude -p` があれば字だけ直す（キー・値・出典は変えさせない。形が変わったら下書きのまま）。アプリの画面の「作る（ハーネスから）」も同じ道具を呼ぶ

### どこから何を取るか
| survey.json の所 | 出典 | 決め方 |
|---|---|---|
| 問い：使う場所（`a`。理由には使わない＝`in_reasons:false`） | A 4章「場面・相手ごとの分岐」の表で「どこに置く」がある行。並びは K `_一覧.md` のアングルの順 | 割引の管理名に残して B に戻す（顧客調査）。理由が3つに足りない時だけ使う |
| 問い：サイズ（`z`） | A 3章「対象の身長」の行（表の頭の型の名前で mini／orig）・A 4章「サイズの選び方」 | 小さい方以下／大きい方／上限を超える（warn・`offer.size_alias` で大きい方へ） |
| 問い：足元（`k`） | A 4章「靴あり・靴下・素足」・A 7章 A-6「靴」（ハイヒール不可 → `fit:"no"`） | 使えない靴だけ no |
| 問い：床（`f`） | A 3章「床への接し方」・A-6「床」（毛足の長いラグ → warn） | 使えないとは書いていない物は warn |
| 合わない（`fit:"no"`） | **A-6 使えない人・場面の行だけ**（作らない） | 理由の1行と `_sources` の行は必ず |
| 最後の不安（`worries.items`・6まで） | 重い順：店の設計.md の疑いの表（08_店）＞記事の移植表「見終わった人の状態」の「残った疑い」＞記事のコメント欄の「よくある質問」（上ほど重い）＞B ⑤の「壁」・K の「壁」。似た問いはまとめる（字の重なり） | 値段の疑いは入れない（おすすめのカードで値段を出す）。返金の質問は理由の固定の1行（`fit.fixed_reasons`）に |
| 答え（`worries.answers`） | FAQ の答え → 無ければ A 4章・2章と E の近い行（5つまで `_sources` に） | A・E の事実だけ。治る・消える・改善・医師・研究の数字は書かない（`check.mjs` が止める） |
| 値段・セット・色 | 記事の `値段の段_入力.json`（セット・値段・色・保証の日数）。無ければ前の設定 | 記事 → 店 → LINE で同じ数字・同じ色 |
| ポップアップ・リッチメニュー | 決まり文句「買う前に、あなたに合うか30秒でチェック」「回答のお礼に1,000円OFF」 | 店のページだけに出す（記事 LP は除く） |

### 画像（元の店の型のまま。増やさない）
`fit_ok`（合います）・`d_<1つ目の不安>`（答えの見出し）・`coupon`・`hero`・`richmenu`・ポップアップのバナー。理由と答えの文は Flex の文で出すので、答えごと・組み合わせごとの画像は作らない（診断の 20〜40枚 → 6枚）。写真は前に作った物（`images/gen.mjs`）を使い回す。

### 立ち仕事マットで回した結果（2026-10-20）
- 出力：`products/tachimat-fitcheck/survey.json`（アプリ）＝ 仮ハーネス `sample/立ち仕事マット/line/survey.json`
- 問い4（場所6・身長3・足元4・床3＝216通り）：合う 73・注意つき 90・合わないかもしれない 54（ヒールのある靴だけ no）。不安6（店に置ける・狭いレジ・本当に腰が重くならない・勝手に動く・靴のまま滑らない・ふらつかない）。候補13から重い順
- 検査 だめ 0件。e2e 37件。画像は写真の使い回しで5枚（生成 0回）

# 前の形：診断（元の店型・悩みを聞く）

商品理解（工程1）が終わった商品フォルダ `newec_harness/<商品>/` から、LINE 診断の設定 `survey.json` を1本作る。作るのは Claude、見て直すのは 運営者。手本は元の店の本番の設定（アプリには入れない）と立ち仕事マット（`sample/立ち仕事マット/line/survey.json`＝この手順で作った物）。

## 読む物（この順。全部は読まない。見出しで探して要る所だけ）
| survey.json の所 | 読む所 | 決め方 |
|---|---|---|
| Q1 困っていること（`questions[0]`） | B ②悩みの割合と順位・④お客さんの原文 | 多い悩みの上位 4〜5。**お客さんの言葉のまま、場面の言葉で**（「2時間もすると腰が重く痛む」）。病名・医学の言葉にしない。元の店は LINE の答えで「作業の言葉ほど選ばれる」と分かっている（元の店の B_市場と悩みの地図 103行目） |
| Q2 いちばんつらいこと（`questions[1]`） | B ④の「つらい場面」・⑤の壁・K-3（今している事・こわい事） | その悩みが一番こたえる時・場面 4つ。結果の画像には使わず、割引の管理名に残して B に戻す（顧客調査の役目） |
| Q3・Q4 その人の条件 | K `_一覧.md`（アングル・使い方の分岐） | 結果の画像を分ける条件（Q3＝場面／年齢など、5まで）と、おすすめの品を決める条件（Q4＝大きさ・サイズ）。選択肢の数の掛け算が結果の画像の枚数（4×5＝20） |
| 結果（`images.cards.result`） | H 1章（根本原因の1文・名前）・8章（アングルへの広げ方） | 見出しは原因を短く（「原因は、止まって立つこと」）。一言2つ＝悩みの側（H の仕組みを悩みの言葉で）と条件の側（場面でどう効くか）。治る・消えるは書かない |
| 不安（`worries.items`・`images.cards.worries`） | B ⑤低評価・壁、返品理由・CS の質問（`~/ec-cs` の記録・店の問い合わせ）、A 5〜7章（仕様・お手入れ・使えない人） | 上位 5つ。答えは A の事実だけで書く。仕入れ品で確かめていない物は `note` に「※確かめてから出す」と書き、`_notes.example_values` に入れる |
| 今の対策（`tools.items`）と費用（`compare.costs`） | D1・D2 の「お金と手間」（値段・交換の目安） | 原文で多い対策から 4〜6（＋「まだ何もしていない」）。3年の費用＝値段×年の回数×3。**うちより安い対策は mode: note（数字で比べない）**、毎年かかる物は chart、1回の大きい費用は single。`basis` に出どころの行を書く |
| クーポン（`coupon`） | 既定：1,000円・24時間・1人1回（元の店） | 変えるのは 運営者 の指示の時だけ |
| おすすめ（`offer`） | 00_入口・02_損益分岐（売値・セット・定期便） | 店ができたら `scripts/pull-variants.mjs --write` で取り直す。それまでの値は仮 |
| ポップアップ・バナー（`popup`・`images.banner`） | 元の店の文の型 | 見出し「LINE追加で無料診断」、副見出しは Q1 の言葉で「◯◯の原因、30秒でわかります」。出さないページ＝記事の LP（`/pages/advertorial`） |
| 写真の場面（`images.photos`） | K のペルソナの年代・場所・服・靴 | style-guide.md 4章 |
| 色（`brand.theme`） | ブランドの色（店の設計 2.5・ロゴ） | style-guide.md 3章。ブランド未定なら仮と書く |

## 頼む文（Claude が自分に、または別の Claude に渡す）
```
あなたは LINE 診断の設計をする。商品フォルダ <newec_harness/<商品>/> を読み、
tools/line-survey/products/tachimat-fitcheck/survey.json と同じ形の survey.json を1本書く。
決まり：tools/line-survey/scripts/survey-from-harness.md の表のとおり。
- 選択肢の字はお客さんの原文の言い回しから（B ④の番号を _notes.sources に書く）。40字まで、ふつうは20字まで
- 選択肢の値は英小文字・数字10字まで。問いの key は1文字（s w g は使えない）
- 結果は H の根本原因の言葉で。治る・消える・医師・研究の数字は書かない
- 費用は D の値段から計算し、basis に式と出どころ。うちより安い対策は数字で比べない（mode: note）
- 店のデータが無い値（ID・値段・LINE の ID）は仮の値にして _notes.example_values に1行ずつ書く
書いたら node tools/line-survey/scripts/check.mjs <survey.json> を回し、だめが0件になるまで直す。
```

## 手順
1. 上の表の順に読み、`sample/<商品>/line/survey.json`（仮ハーネス）か `products/<id>/survey.json` に書く
2. `node scripts/check.mjs <survey.json>` → だめ 0件まで直す（注意は残ってよい）
3. 画像：`node images/gen.mjs <survey.json> <gen>` → `python3 images/make_images.py <survey.json> <gen> <img>`
4. 運営者 に、問いと結果の文・画像を見せる（元の店との並べ見せ：`sample/立ち仕事マット/line/contact-sheet.html` の形）
5. 店ができたら `scripts/pull-variants.mjs --write` → `_notes.example_values` から消す → `check.mjs --deploy` が 0件

## 立ち仕事マットで回した結果（2026-10-20）

- Q2：B ④の「仕事の終わりに立っているのがやっと」系・「休みで消えて月曜に戻る」（H 2章の症状）・湿布と痛み止め（④-26・19）
