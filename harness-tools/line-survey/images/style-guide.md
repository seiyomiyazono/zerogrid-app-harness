# LINE の画像の決まり（元の店の実物から。2026-10-20）

元：元の店の画像（結果・不安の答え・比べる・クーポン・定期便）・`assets/richmenu.jpg`・ポップアップのバナー。作り方の元は `tools/make_images.py`（文字入れ）と `gen/gen1.sh`（写真）・`prompt-C2.txt`（バナー）。

## 1. 2つの作り方
| 画像 | 作り方 | 理由 |
|---|---|---|
| 結果・不安の答え・比べる・クーポン・入口・定期便・リッチメニュー | **写真は AI（文字なし）＋文字は make_images.py で後から入れる** | 字を AI に書かせると誤字が出る。数字（値段・3年の差）を設定から入れられる |
| ポップアップのバナー（3:4） | **AI に字ごと描かせる**（太い丸ゴシック・イラスト） | 店の上に出すので目立つ絵柄。字は短く、生成後に目で誤字を見る |

写真は実写風（人・部屋・物）。イラストはバナーだけ。商品写真（定期便で届く物など）は店の本物を使い、AI で作らない。

## 2. 型（1040×1040 の正方形）
| 型 | 使う所 | 並び |
|---|---|---|
| A 写真の上に文字（hero_card） | 結果・入口（hero）・定期便のおすすめ | 写真を全面。上 470px を白く溶かす。左上に枠つきの小さな札（「レジ × 腰」）、右上にロゴ、明朝 84px の見出し2行（左寄せ）、白い帯の上に一言2つ（36px）、下に黒帯 110px（白字 42px）、右下に斜めの三角 |
| B 白い額（card） | 不安の答え・クーポン・比べる（数字で比べない時） | 写真を白で 40〜55% 薄める。中央に白い額（半透明・金の細線＋内側に黒の細線）。上から 問い（44px）→ 大きな答え「大丈夫です」（104〜116px）→ 色の帯「心配ないです」（40px・字間 8）→ 一言 1〜3行（40px）→ 小さな注（22px・灰）。クーポンは下に黒帯 |
| C グラフ（chart） | 比べる（今の対策が毎年かかる時） | 写真を 82% 薄める。見出し「◯◯と比べると」46px → 差「3年で ◯円 の差」64px（帯の字の色）→ 1〜3年目の棒（今の対策＝灰、うち＝テーマの色）→ 凡例 → 「※購入費の一例（出どころ）」24px |
| C' 2本の棒（single） | 1回の費用どうし（しつけ教室・整体） | 同じ。棒2本に値段を上に、名前を下に |
| D リッチメニュー（2500×843） | トークの下 | 左 1660px：写真を右寄せ、左から白く溶かす。見出し明朝 120px 2行 → 色の帯（58px）→ 一言 52px → 黒い角丸ボタン「タップして診断 ›」。右 840px：薄い地にロゴ（無ければ wordmark）と「商品を見る ›」。1MB 以下の JPEG |
| E バナー（1086×1448・3:4） | 店のポップアップ | 白〜淡い地のグラデ・角丸。主見出し（太い丸ゴシック・テーマの濃い色）→ 副見出し → 商品のイラスト＋緑の吹き出しとチェック3つ → チケット型の帯（白字、金額だけ大きく）→ LINE の緑 #06C755 の角丸ボタン「ここから追加」→ 小さく「友だち追加は無料・いつでも解除できます」 |

字は全部 明朝（ヒラギノ明朝 W6 見出し・W3 本文）、英字の帯は Didot（字間 10）。元の店の「MYTREX 型」＝上品・余白が多い。

## 3. ブランドに合わせて替える物（survey.json の brand.theme）
| 札 | 元の店 | 替える基準 |
|---|---|---|
| `band`（帯の地） | 淡い水色 #D0E8F7 | ブランドの色を白で 80〜85% 薄めた色 |
| `band_text`・`chart`（帯の字・うちの棒） | 青 #1E5A96・#54A0D2 | ブランドの濃い色・中くらいの色 |
| `primary`（Flex のボタン・リッチメニュー右の字） | 濃紺 #032878 | ブランドの主の色（白字が読める濃さ） |
| `corner`（右下の三角） | コーラル #E88C6E | ブランドの差し色（主の色の反対側） |
| `frame`（額の金線）・`bar`（黒帯）・`ink` | 金 #B8A07A・#121212・#1C1C1C | 基本は替えない（型の上品さを保つ） |
| `photo_mood`（写真の色味） | 白とベージュ | ブランドの地の色。写真の文に足される |
| `banner_bg_name`・`ticket_name`・`primary_name` | 淡い水色・オレンジ・濃紺 | バナーの文に入る色の名前 |
| ロゴ | `logo-new.png`（小）・紺の大ロゴ（リッチメニュー右） | 無ければ `wordmark` を Didot で置く（仮） |
| フォント | 明朝 | 替えない。ブランドがゴシックなら font_heading だけ替える |

立ち仕事マット（仮）：深い緑 #2D5A47・帯 #DCEBE3・差し色 #E3A04F（ブランド未定なので仮）。

## 4. 写真の文の型（images/prompts.mjs）
`<場面>。色味：<photo_mood>。上質なライフスタイルブランドの広告写真のトーン、やわらかい自然光、文字・ロゴ・透かしは一切入れない、正方形。`
- 場面は survey.json の `images.photos`。人＝客と同じ年代・場所（K のペルソナ）。結果の写真は「条件ごと」に1枚（元の店は年齢ごと、立ち仕事マットは立つ場所ごと）で、悩みの違いは文字で出す
- 商品の形が独特な時は、形を言葉で細かく書く（「前に横長の棒状の盛り上がり、中央に低い山、左右にゆるい坂」）。仕入れ品の写真が来たら参照画像に替える
- 結果の写真は「つらそう」より「楽に立っている」（元の店も結果は笑顔の犬）

## 5. 言ってはいけない事（画像の字も）
- 薬機法：治る・痛みが消える。言うのは「原因」「足が置きかわる」「楽」まで
- 作らない物：レビューの件数・星・医師の顔と名前・研究の数字（出どころの無い物）
- 比べる画像で、うちが高いのに安く見せない（安い対策は C の数字にせず B の「ここが違います」にする）
- 「※」の出どころは survey.json の `compare.costs.*.basis` から入る。仮の数字のまま出さない（check --deploy が止める）

## 6. 生成の道
`HIGGSFIELD_API_KEY` があれば Higgsfield（Zero Grid の鍵・未着・未検証）、無ければ Codex CLI（`~/.local/bin/codex exec`、ChatGPT ログインの画像生成。元の店と同じ道）。混み合いで失敗したら同じ物だけ `--only <名前>` で回し直す（2026-10-20 に1枚「model is at capacity」で失敗→回し直しで成功）。
