# 使う人（運営者）に聞くこと

特商法の表記・ポリシー・お問い合わせフォーム・CS の返信は、どれも「会社・ストア・商品」の値で決まる。値を1か所に集めて、全部をそこから作る。ここには、何を・どう聞くかを書く。

- 聞く項目の正本：`scripts/store-legal/questions.json`（仮ハーネスでは `~/.agents/skills/ec-ad-ops/scripts/store-legal/questions.json`）。下の表は、そこから作った写し。項目を足す・直す時は JSON を直してから、この表を作り直す。
- 値の置き場：会社＝`harness/_運営者/<会社>/運営者情報.json`、ストア＝`harness/_運営者/<会社>/ストア/<店>.json`、商品＝`<商品フォルダ>/08_ストアの決まり.json`。形は `harness/_運営者/_ひな形/`。
- 書類を作る道具：`scripts/store-legal/render.mjs`。足りない値があれば書類を出さずに、聞くことを出して止まる。

## 1. 聞く順番（一度にまとめて1回）

1. **AI が先に調べる。** 聞く前に、分かる物は全部埋める。
   - 会社：`harness/_運営者/` に、その運営者の `運営者情報.json` がもうあるか。あれば会社の質問はしない（変わった所だけ確かめる）。
   - ストア：運営者の Shopify から読む（`node scripts/store-legal/probe-store.mjs --env ~/.config/secrets/shopify-<保存名>.env`。読むだけ）。店名・URL・問い合わせのメール・請求先の住所（会社の住所の候補）・今のポリシー・定期の販売プラン・テーマの色が取れる。支払い方法は API で全部は取れないので、お店の下の決済アイコンを共通 Chrome で見る。
   - 商品：商品フォルダの `00_入口.md`（呼び名・売値・定期便）、`01_商品理解の基盤/` の A（慣らしの日数・口コミ）・H・I（使い続ける理由の文の案）、サイズや色があるか。
2. **足りない物だけを、1回のメッセージでまとめて聞く。** `render.mjs` を空のまま流すと、足りない質問が会社・ストア・商品の順に出る。その文をそのまま使ってよい。
   - 初期値がある物は「◯◯でよいですか」と確かめる形にする。答えが「全部初期値でよい」なら `--accept-defaults` を付けて作る。聞いていない初期値で書類を出さない。
   - 未決（P1〜P8、`NOTES-policy-cs.md`）の項目は、初期値を選んだ理由を1行添える。
3. **答えを JSON に入れる。** 形が合わない値（郵便番号・電話・URL・メール）は、`render.mjs` が「形が合わない」と言うので、聞き直す。
4. **書類を作る → 点検 → 見せる。** `render.mjs` の点検（日数・返金額が全部の書類で同じか、合わない言葉が残っていないか）が通ってから、運営者に見せる。Shopify に入れるのは OK の後（`install-shopify.mjs --apply`）。

聞くのは3回の時だけ：会社は運営者が初めて使う時に1回、ストアは店を足す時に1回、商品は店（PDP）を作る時（工程4d）に1回。

## 2. 住所と電話を出さない選び方（開示請求）

特商法のページで、住所・電話・メールを「ご請求をいただければ、遅滞なく開示いたします」にする選び方を出す（`operator.disclose_on_request`）。初期値は「住所と電話は載せる、メールだけ開示請求」（今の決まり）。

- 特定商取引法 第11条ただし書で、広告に「請求があれば遅滞なく提供する」と書き、実際にすぐ出せる用意をしている時に、一部を省ける。返品の決まり（返品特約）や、前払いの支払時期などは、省けない。
- 「遅滞なく」は、申し込むかを決める前に、十分な時間の余裕をもって出せること。メールでの提供でもよい。
- これは消費者庁の説明の要約で、法律の判断ではない。住所・電話を省く時は、出す前に専門家（弁護士など）に確かめる、と運営者に伝える。
- 住所を表に出さなくても、プライバシーポリシーには事業者の住所（法人は代表者の名前も）を書く（個人情報保護法32条）。テンプレートはそうなっている。
- 出どころ：消費者庁 特定商取引法ガイド「通信販売」 https://www.no-trouble.caa.go.jp/what/mailorder/ ／法令（e-Gov）特定商取引法 https://elaws.e-gov.go.jp/search/elawsSearch/elaws_search/lsg0500/detail?lawId=351AC0000000057 ／通信販売の申込み段階における表示についてのガイドライン https://www.no-trouble.caa.go.jp/pdf/20241119la02_09.pdf ／返品特約の表示のガイドライン https://www.no-trouble.caa.go.jp/pdf/20230421la02_07.pdf （2026-10-20 に消費者庁のページを読んで確かめた。PDF の中身は読んでいない）

## 3. 聞き方の決まり

- やさしい言葉で聞く。法律の言葉（「表示義務」「返品特約」）は、なぜ要るかの欄にだけ書く。
- 鍵・パスワードは聞かない。Shopify・Gmail・LINE は、運営者がログインして許可するだけ（`skills/ec-cs/references/接続.md`）。
- 見本の値（questions.json の example・`_example` の印）を、運営者の書類に使わない。見本の値で作った書類は `index.json` に `"example": true` が付き、`install-shopify.mjs --apply` が止める。
- 商品の「使い続ける理由の文」は、AI が商品理解の基盤から案を1本出し、運営者が直す。効果を約束する言葉（「治る」「必ず」）を入れない。
