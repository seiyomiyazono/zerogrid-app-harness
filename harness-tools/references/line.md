# 工程4d の後：LINE 診断を店に付ける — 元の店の LINE を商品ごとに作る（2026-10-20・仮）

運営者「LINE は商品ごとに作れるように。元の店の LINE をそのまま骨組みにし、画像・リッチメニューも元の店のデザインを土台に、商品・ブランドのテーマに合わせて作る」。店（PDP）ができた後に、店に付ける部品の1つとして作る。道具は `ec-ad-ops/tools/line-survey/`。


## いつ・だれが
| 場面 | やること |
|---|---|
| 店（4d）が審査 PASS して非公開テーマに置かれた後（同じ回） | この工程。店の部品（特商法・ポリシー・問い合わせ＝`store-legal.md`）と一緒に出す |
| 商品理解（工程1）が直った・LINE の答えで悩みの順位が変わった | 2〜4 だけ回し直す |
| 1つの言葉・画像を直すだけ | 3 と 6 だけ |
| 記事 LP（`/pages/advertorial-*`） | ポップアップを出さない（記事の A/B テストを汚さない）。店のページだけに出す |

作るのは Claude。アカウントは使う人の物（LINE・Shopify・Vercel。`アカウントの持ち主.md`）。使う人がするのはログインと、LINE 公式アカウントの作成フォーム・認証の申請だけ。

## 入れる物
| 物 | 置き場 |
|---|---|
| 商品理解 | `01_商品理解の基盤/` の B（②順位・④原文・⑤壁）・H（1章・8章）・K（`_一覧.md`）・D1/D2（お金と手間）・A（5〜7章） |
| 売値・セット・定期便 | `00_入口.md`・`02_損益分岐.md`、店ができていれば店の公開データ（`pull-variants.mjs`） |
| ブランドの色・ロゴ | 店の設計 2.5（見た目の方向）・ブランド名（`naming.md`） |
| 返品・問い合わせの声 | `ec-cs` の記録（あれば。新しい商品は B ⑤で代える） |

## 手順
1. **設定を作る**：`tools/line-survey/scripts/survey-from-harness.md` の表のとおりに `survey.json` を1本書く（問い4つ・結果・不安・今の対策と3年の費用・クーポン・おすすめ・ポップアップ・リッチメニュー・写真の場面）。店のデータが無い値は仮にして `_notes.example_values` に書く
2. **検査**：`node tools/line-survey/scripts/check.mjs <survey.json>` → だめ 0件まで 1 に戻る。LINE の上限（ボタン40字・postback 300・カルーセル12枚・1回5通・URL 1000字）と、押せる道を全部たどった時の返事を数える
3. **画像**：`node images/gen.mjs <survey.json> <gen>`（写真・バナー。Higgsfield の鍵があれば Higgsfield、無ければ Codex）→ `python3 images/make_images.py <survey.json> <gen> <img>`。決まりは `tools/line-survey/images/style-guide.md`（元の店の型・色の替え方・言ってはいけない事）
4. **見せる**：問いと結果の文、画像を元の店と並べた1枚（`sample/立ち仕事マット/line/contact-sheet.html` の形）を 運営者 に見せる。**運営者 の OK の後に 5 へ**
5. **店の数字を入れる**：`scripts/pull-variants.mjs <survey.json> --write`（バリアント・値段）→ 仮の値を消す → `check.mjs --deploy` が 0件
6. **立ち上げ**：`tools/line-survey/README.md` の表の 0〜14（LINE のログイン → アカウント → Messaging API → 鍵 → Shopify の鍵 → Vercel に出す → Webhook → LIFF → リッチメニュー → 店のポップアップは非公開テーマへ）。全部 dry-run で通してから `--apply`。人の手番（ログイン・フォーム・認証の申請・実機の確認）はまとめて1回で頼む
7. **公開**：公開テーマへのポップアップ（`--main-ok`）と、広告からの人を LINE に流すのは **運営者 の OK の後だけ**
8. **測る**：1週間ごとに、友だち追加（`line-api.mjs <id> quota`・Insight）・答え終わった数（Shopify の割引の管理名「LINE◯◯｜…」）・LINE クーポンの注文を数え、答えの分布を B ④の後ろに足す（元の店の B と同じ形）

## 承認
| 物 | 誰が |
|---|---|
| 問い・結果の文・不安の答え・費用の数字 | 運営者（4） |
| 画像・リッチメニュー・ポップアップのバナー | 運営者（4） |
| クーポンの額と時間（既定 1,000円・24時間・1人1回） | 運営者（変える時だけ） |
| LINE・Vercel・非公開テーマへの書き込み | 運営者 の OK の後（6） |
| 公開テーマへのポップアップ・広告からの誘導・一斉配信 | 運営者 の指示の時だけ（7）。一斉配信はプッシュで通数を食う（無料は月200通） |

## 出す物
- `newec_harness/<商品>/08_店/LINE/survey.json`・`img/`・`contact-sheet.html`（本物に入れた後の置き場の案）
- 鍵：`~/.config/secrets/line-<id>.env`（値は出さない）
- 依頼票・00_入口の進みの表に「LINE ずみ <日付>」

## やってはいけない事
- プッシュで送る形にしない（待ちの後も返信で返す。元の店は今月 0通）。クイック返信・Lステップは使わない（`article/クイズファネル/LINEで回す.md` の理由と同じ）
- 治る・消える・医師・研究の数字を、問い・結果・画像の字に入れない
- うちより安い対策を、数字で比べて高く見せない（mode: note）
- 仮の値のまま出さない（`check.mjs --deploy` が止める）
- Manager のあいさつメッセージをオンのままにしない（Bot のあいさつと二重になる）
