# ストアの決まりの文書（特商法・返金・規約・配送・プライバシー・連絡先・定期便）

全商品共通の決まり。店（PDP）を作る時に、ここを読んで書類を出し、Shopify に入れる。値は「会社・ストア・商品」の3つの設定に置き、ここにもひな形にも会社の名前や住所を直に書かない。

- 何を聞くか：`references/operator-intake.md`（正本は `scripts/store-legal/questions.json`）
- 値の置き場：会社＝`harness/_運営者/<会社>/運営者情報.json`、ストア＝`harness/_運営者/<会社>/ストア/<店>.json`、商品＝`<商品フォルダ>/08_ストアの決まり.json`
- ひな形：`templates/store-legal/`（特定商取引法に基づく表記・返品・返金ポリシー・利用規約・配送ポリシー・プライバシーポリシー・連絡先情報・定期便ポリシー、と同じ文を使い回す `_部品/`）
- 道具：`scripts/store-legal/`（`probe-store.mjs` 読む／`render.mjs` 作る／`install-shopify.mjs` 入れる）、お問い合わせページは `templates/contact-page/`（`build.mjs`）

## 1. 流れ（店を作る時＝工程4d）

1. **調べる**：運営者の会社の設定があるか見る。無ければ `operator-intake.md` の会社の質問をする。ストアは `probe-store.mjs` で Shopify から読む。
2. **聞く**：`node render.mjs --operator … --store … --product … --out <商品フォルダ>/08_店/policies` を流す。足りない値があれば、聞くことが出て止まる。まとめて1回で聞く。
3. **作る**：答えを JSON に入れて、もう一度流す。「初期値でよい」と言われた時だけ `--accept-defaults` を付ける。Markdown と HTML（Shopify 用）と `index.json` が出る。
4. **点検**：`render.mjs` が自動で見る（下の5章）。問題があると終了コード 3 で止まる。
5. **お問い合わせページ**：`node templates/contact-page/build.mjs …` で、同じ値から `page.zg-contact.liquid` を作る。
6. **入れる**：`node install-shopify.mjs --dir <出力> --contact <liquid> --theme-id <非公開テーマ>` は DRY-RUN（送る中身を見せるだけ）。運営者の OK の後に `--apply --env ~/.config/secrets/shopify-<保存名>.env`。見本の値の書類は止まる。
7. **公開ページで確かめる**：`/policies/legal-notice` ほか、`/pages/contact` を共通 Chrome で開き、日数・返金額・店名が同じか見る。
8. **CS にも同じ値を渡す**：`ec-cs` の config に、同じ3つの設定の場所を書く（`profiles`）。返信の決まりは `render_rules.mjs` で同じ値から作る。

Shopify のポリシーの種類（Admin GraphQL `shopPolicyUpdate` の `ShopPolicyType`、2026-10 で確かめた）：LEGAL_NOTICE・REFUND_POLICY・TERMS_OF_SERVICE・SHIPPING_POLICY・PRIVACY_POLICY・CONTACT_INFORMATION・SUBSCRIPTION_POLICY（定期便がある時だけ）。アプリには `write_legal_policies`（ページは `write_online_store_pages`、テーマは `write_themes`）が要る。

## 2. 返金保証の決まった形（初期値＝標準の型。スキルの ec-ad-ops/references/store-legal.md 1章と同じ 30日・15日。店の部品の画面・ダルマの下書き・書類で同じ初期値を使う）

| 項目 | 初期値 | 設定の場所 |
|---|---|---|
| 保証の日数 | **30日**（商品到着日から）。45日・60日などに変えられる | `product.guarantee_days` |
| 使う日数 | **保証の日数の半分**（30日なら15日。割り切れない時は切り上げ：45日なら23日）。この日数を過ぎるまでは申し込めない。別には決められない | 計算（`product.use_days`。`lib.mjs` の derive） |
| 申し込める期間 | 到着から（使う日数＋1）日目〜保証の日数の日目（30日なら16日目〜30日目） | 計算（`c.apply_window`） |
| 使う日数（15日）以内の申し込み | **受けない** | `product.early_refund`＝none／partial |
| 返金額 | 支払った全額 | `product.refund_rate`＝100 |
| 使った後の商品 | 対象 | — |
| 手続き | フォーム → 写真 → 返送先の案内 → 返送（送料はお客さま）→ 追跡番号 → 届いて確かめて返金確定 | — |
| 返送先 | 会社の事務所（例：「<会社名> <店名>返品係」）。書類には書かず、手続きの時に案内する | `operator.return_address` |
| 返金が完了するまで | 確定から最大60日 | `store.refund_max_days` |
| 複数点 | 同じ注文の全部を返送。保証は1注文に1回 | — |
| 不良・破損・欠品・違う商品 | 期間の条件なし・写真・送り返し不要・再送か返金を選んでもらう（2026-10-18） | `product.defect` |

商品で変える時は、運営者が決めて、商品の `08_ストアの決まり.json` に書く。返金が100％でない時は「返金保証」「全額」と書かず、「お試し保証」など別の名前にする（`render.mjs` が止める）。

## 3. 連絡先とお返事

- メールアドレスは、初期値では載せず「ご請求をいただければ、遅滞なく開示いたします」と書く（`operator.disclose_on_request`）。住所と電話も同じ書き方を選べるが、条件がある（`operator-intake.md` 2章）。
- お問い合わせは、すべてお問い合わせフォームへ案内する。電話を受けない時は「お電話でのご対応は行っておりません」を添える。
- お返事と返金の手続きは、営業日（`operator.business_days`）だけ、と書く。

## 4. 文の調子

- 冷たい言い回しを避ける。「〜する義務を負いません」「責任を負いかねます」を、返金・特商法のお客さま向けの説明では使わない（配送ポリシーの免責の節だけは残す）。
- 先に使い続けてもらう理由を書き、その後に条件を書く。理由の文は、商品理解の基盤から取る（`product.reason_sentence`）。
- 発送元を「海外」と書かない設定（`store.ship_origin`＝warehouse）では、「海外」「通関」「国際物流」を書かない。ただしプライバシーポリシーの「外国にある第三者への提供」は、`store.cross_border` で別に決める（CS のメールと、法律の書類は別）。

## 5. 同じことを、全部の場所で言う（一番大事）

次の場所の、日数・返金額・条件を、1字も違えない。全部が同じ設定から作られるので、変える時は設定を直して作り直す。手で1か所だけ直さない。

1. 商品ページ・トップ・記事の保証の説明（`pdp-tsukuru` が `08_ストアの決まり.json` を読む）
2. カートのボタンの近くの表示
3. 返品・返金ポリシー
4. 特定商取引法に基づく表記
5. 利用規約の第7条
6. お問い合わせフォームの選択肢と説明
7. CS の返信の決まり（`ec-cs` の `render_rules.mjs`）
8. よくある質問、口コミの文
9. 広告の原稿（商品の `05_原稿の決まり.md`）

- ページで「◯日間返金保証」と書く所には、すぐ近くに「◯日以上お使いいただいた後、◯日以内のお申し込みが対象です」と「返送料のみご負担ください」を書く。条件を規約だけに書かない。
- 返品の決まりは、特商法で最終確認の画面（カート・購入手続き）にも出す決まりがある。カートの近くの表示を省かない。
- 「すぐ返金」「手続きなし」のような、実際の手続きと合わない言葉を使わない。

## 6. 出す前の点検（`render.mjs` が自動で見る物と、人が見る物）

自動：
- 特商法・返金ポリシー・規約に、申し込み期間と返金額が同じ文で入っているか
- `{{ }}` が残っていないか
- 「海外」と書かない設定なのに海外の言葉が無いか／全額でないのに「全額」「返金保証」が無いか／体に使わない商品なのに免責の文が無いか

人：
- 5章の 1・2・8・9 は書類の外にあるので、同じ数字か目で見る
- その店で本当に使える支払い方法か（後払いが無ければ入金の文は出ない）
- 見本の値（`"example": true`）のまま入れていないか
- ストアへの書き込みは、運営者の指示がある時だけ
