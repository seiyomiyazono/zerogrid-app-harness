# 運用規律（v6・2026-08-20 運営者の監査を受けて追加）

このファイルは「調べ方」ではなく「**同じ失敗を二度やらないための縛り**」。毎回読む。

## 1. 競合表に載せる前に実物を見る（違反＝レポート無効）

**商品名から商品を推測して競合表に載せてはいけない。**

必ず `products.json` の `body_html`、または商品画像を取得して、**「これは何なのか」を自分の言葉で1行書く**。
書けないものは競合表に載せず、別枠の「未検証」に落とす。

失敗例（2026-08-20・首の後ろのコブ 70点レポート）。実物を見たのは FisioRest 1社だけで、残りは名前で分類した。

| 表に載せた競合 | 実際 | |
|---|---|---|
| Artuvate FisioRest $89 | 26°傾斜フォームブロック・非電動（画像で確認） | ✅ |
| VertiClear Pro $89.99 | 同じ店に「**EMS導電ジェル**」＝電動EMS機器。入口も「めまい」 | ❌ 別商品 |
| KyroLabs Cerviflex | 商品一覧に「**Replacement Pump**」＝空気で膨らませる牽引器 | ❌ 別商品 |
| Kanuda Head Nap $192 | 韓国の**頸椎枕** | ❌ 別商品 |

しかも同じレポート内に「電動は隣接クラスタ」という箱を自分で作りながら、VertiClearとKyroLabsを本表に残していた。
**分類ルールを作って自分で守れていない。**

成功例（同日・耳栓 レポート）。全部 `body_html` を読んでから弾いた。
```
klar    → "Restaurants, gatherings" = 会食用フィルター → 除外
CURVD   → products.json がマグカップだった          → 除外
Reson   → "Moto Earplugs 12-32dB" = バイク用        → 除外
Mack's  → 使い捨てフォーム                          → 除外
```
**差は「商品説明を実際に読んだかどうか」だけ。**

## 2. 同じ証拠は全案件で同じ扱いにする

2026-08-20、インソールのレポートにはこう書いた。
> Hookdの日本語インデックスで0件。ただし日本語クエリのカバレッジが薄いため、**「空白」の証拠には使えない**

同じ日の耳栓レポートでは、同じ `geo=JP` 0件を**空白度15点の根拠にした**。
**自分で「使えない」と書いた証拠を、都合のいい方だけ採用している。** これで83点が出た（監査後74点）。

証拠の格付けを先に決めて、全案件で固定する。案件ごとに変えない。

## 3. 市場規模は「買う人の数」で数える

悩んでいる人の数ではない。

- ❌ 耳栓の市場に「睡眠で休養がとれていない2,500万人」を全部当てた。休養不足の理由が隣のいびきである人は一部
- ❌ 「睡眠時無呼吸 2,200万人」も**いびきをかく側**であって、耳栓を買う人ではない
- ✅ 買う人（その隣で寝ている人）を推定し、推定であることを明記する

## 4. スクレイパーは1件で動作確認してから全件回す

2026-08-20、正規表現とセレクタのミスで**4回空振り**（`view_all_page_id` リンクが存在しない／件数の正規表現が
`検索結果: 約11件` に当たらない／innerHTMLに初回分しか残らない／収穫0）。約45分溶かした。
**壊れたスクレイパーを本番で直しながら回していた。**

新しい取得経路を書いたら、必ず1件で流して**期待した値が入っていることを目で見てから**全件に回す。

## 5. 直列で回さない

タブ1枚で450社を叩いて35分。8タブに並列化したら350社が6分になった。
アプリでは zg の research_stores が8店ずつ同時に測る（1回40店まで）。**測る店はまとめて渡す。**

## 6. 測ったものは保存する。二度測らない

zg の research_index（research/banger-index.json）に `{pageId: {nm, dom, ads, at}}` で貯める。店を測った物は research_stores が research/store-gate.json に貯める。
毎回ゼロから測り直さない。

## 7. 必須を満たさない商品を運営者に差し出さない

確定は `確定の判定の決まり.md` の必須7つ（2026-10-18：点数は付けない。前の合格ライン80は使わない）。満たさない候補は**台帳に見送りとして記録するだけ**で、成果物として見せるものではない。
見つからなかった時は「まだ見つかっていない。次はここを掘る」と言う。

2026-08-20、SimilarWebが403・Metaが空を返し始めた時点で探索を止め、手元で一番マシな70点を
「選択肢3つ」の形で提示した。**選ばせる形にしたことで、止まったことが妥当に見えてしまった。** 実際は当たりが既にリストにあった。

## 8. 候補を「商品数」で捨てない

`products.json` の商品数が多いだけで落とすと、Vion（39商品・広告3,271本が Fade 1商品に集中）を落とす。
同じ理由で Histrips（56商品・鼻腔ストリップ・1,697本・訪問644K）も落としている。**再確認する価値がある。**

判定は `dropship-check.md` の**主力商品への広告集中度**で行う。
