# レポート必須構成（v5.2・運営者指定 2026-08-18 / フォーマット確定 2026-08-20）

**HTMLの型は `report-template.html`（A案・データシート型）が正。毎回この型で出す。**
散文を書かない。表と数字タイルだけで組み、地の文は `.hint`（表の下の注記）と `.flag`（成否を決める一行）だけ。
セクション順は固定: ヘッダー → 数字タイル4枚 → 01競合サイト → 02native → 03advertorial → 04VSL → 05アカウントTop3 → 06日本 → 07スコア → 08参入コンセプト → 09ネクストアクション。
**競合サイトの表には必ず「月間訪問数 / Global Rank / 広告本数 / 最長継続 / ストア年齢 / 価格」の列を持たせる**（運営者指示 2026-08-20）。

確定した1商品について、**同一商品を売っている競合から**以下を必ず揃える。集まらない候補は確定にしない。

**本数はそのままスコアになる（`scoring.md` のスワイプ在庫20点）。** 3枠それぞれ 0本=0／1-2本=2／3-5本=4／6-10本=6／11本以上=7点、合計20でクランプ。
数えるのは**型**であって広告本数ではない。**同一ブランドの同一型のバリアントは1本に畳む**（複製で水増ししない）。
「存在は確認したが個票を取っていない」ものは**0点**。数えたければ実際にコピーを読んで型を判別すること。

## 1. 競合サイト 3つ以上（多いほど良い）
実URL（PDP or LP）。それぞれ: ストア名 / 商品名 / 価格とオファー / ファネル型 / DS判定の根拠1行。
**3つとも同一商品であること**（`same-product-rule.md`）。

**「うまくいっている」の判定基準は `metrics.md` が正。**継続30日以上かつ同一型3本以上、またはperformance_score 81以上。満たさず継続だけ長いものは「最長継続◯本」と正直に呼ぶ。

## 2. native ads（3本は最低ライン。型は多いほど良い）
フィードで個人投稿に見える静止画＋長文コピー型。
それぞれ: ブランド / 継続日数 / performance_score / share_url / **フックの1行**。

## 3. advertorial（3本は最低ライン。型は多いほど良い）
記事型LP（`/pages/...` の体験記・医師ペルソナ・リスティクル）。
それぞれ: 記事URL / 送客元広告のshare_url / 継続日数 / **記事の型**（体験記・専門家告発・比較記事のどれか）。
**advertorialを回している時点でほぼドロップシップ**（自社ブランドはこの型を使わない）。DS判定の証拠として扱ってよい。

## 4. VSL（3本は最低ライン。型は多いほど良い）
動画広告。それぞれ: ブランド / 尺 / 継続日数 / share_url / **冒頭30秒の要旨**（search_ads の transcripts かキーフレームで実測。取れなければ取れないと明記）。

## 5. 一番うまくいっている広告アカウント Top3
ブランド単位のランキング。それぞれ: ブランド名（サイトへのリンク）/ active_ads / 最長継続日数 / performance_score / 推定出稿レンジ（ad_spend_range があれば）/ 何が効いているかの1行。

## 6. 定点観測（1回目でも必ず記録する）
zg の research_stores（observe:true）で競合各社を観測し、research/観測.json に残す。
レポートには **ストア年齢 / Global Rank と前月比 / 推定訪問数 / 3経路の売上逆算**を載せる。
2回目の観測がある商品は**増分**も載せる（伸びているか枯れているか）。詳細は `metrics.md`。

## 揃わない時
埋められない枠は**空欄にせず「取得できず＋理由」と書く**。捏造・別商品での代用は禁止。
枠が2つ以上埋まらない候補は、実証不足として見送りにする。
