# アプリの中で画像を作る時の手順（Zero Grid アプリ用・2026-10-26）

画像の決まりの正本は、それぞれの手順書です（ZackDFilms の絵は `ec-ad-ops/references/video-formats/v1-zackdfilms-video.md` の 18章、静止画は `ec-static-ads`、ほかの動画の型はそれぞれの md）。**この文書は、その手順をアプリの中でどう実行するかだけを書きます。手順の中身は変えません。**

## 1. なぜこの文書があるか

2026-10-26 の通しテストで、アプリで作った絵コンテの質感が、元の環境（運営者の Mac で手順書どおりに作った物）より大きく落ちました。手順書は同じでした。落ちた原因は3つです。

1. アプリにスキルを入れる時に、**見本の絵（本物のコマ・質感の切り抜き・承認された 847 の絵）と、指示の見本の文（.txt）を全部外していた**。手順書が「渡す」と書いている物が、アプリの中に無かった。
2. アプリの画像作りが、**文だけを Codex に渡し、見本の絵を添付していなかった**。指示の文も 2000 字で切っていた（18章の指示は 1段で 1,500〜4,000 字）。
3. 1回の返事で**1枚・1段しか作れなかった**。18章は「段0→段1〜5」を1コマずつ重ねる作り方なので、文だけで1枚描いて終わっていた。

今はこの3つを埋めてあります（見本の絵と見本の文を同梱・`refs` で添付・`steps` で段を重ねる・文は 12,000 字まで）。**手順書に「見本・参考・本物のコマを渡す」とある所を、文だけで描いてはいけません。** それをすると、また同じ落ち方をします。

## 2. 画像の頼み方（返事の最後の `<zg>` の中）

```json
{"image": {
  "name": "packA_01_場面01",
  "aspect": "2:3",
  "steps": [
    {"prompt": "（段1の指示の全文）", "refs": ["skills:ec-ad-ops/references/video-formats/zackdfilms/質感847/参考/1_構図と質感/F_絵コンテ用の構図/構図_水色の居間の女性.png", "skills:…/3_質感_服.png", "skills:…/S2_質感_左が服_右が水色のかべ.png"]},
    {"prompt": "（段2の指示の全文）", "refs": ["skills:…/構図_水色の居間の女性.png", "skills:…/H6_ぼけ_中くらい_後ろの人がとける.png", "skills:…/2b_質感_低い細かさの女性.png", "skills:…/H7_ぼけ_中くらい_後ろの部屋がとける.png", "$1"]},
    {"prompt": "（段3）", "refs": ["$2", "とじ寝/07_納品/画像/人物の見本_20261026.png", "skills:…/T10_顔_女性_電話_短い髪.png", "skills:…/T07_顔_男性_白Tシャツ_赤毛.png", "skills:…/T13_顔_操縦士_白シャツ.png"]}
  ]
}}
```

- `refs` は渡した順に Image 1, Image 2, … になります（最大5枚。18-1「参考画像は5枚まで」）。
- 道の書き方：`skills:<スキルの中の道>`＝同梱の見本の絵。`<商品フォルダ>/<中の道>`＝ハーネスの中の絵（人物の見本・商品の写真・前に作った絵）。`$1`・`$2`…＝この `steps` の1段目・2段目で出来た絵。
- `steps` は最大6段。最後の段が出来上がりで、途中の段は `<商品>/07_納品/画像/_段/` に残ります。段を1つだけ作り直す時は、その段の前の絵を `refs` に入れて、その段から頼みます。
- 何場面も作る時は `"images": [ {…}, {…} ]`（最大12枚。同時に3枚ずつ。18-6 の 16「Codex は同時3本まで」と同じ）。
- 縦の動画の絵は `"aspect": "2:3"`（gen.sh と同じ）。静止画広告は手順書の比率。
- 1段は 1〜15分かかります。返事を出した後もアプリが作り続け、出来た物はそのダルマのスレッドに添付されます。
- 置き場：ふつうは `<商品>/07_納品/画像/<name>_<日付>.png` に置かれます。**店の絵（pdp-tsukuru の `_gen/<名前>.png`）や記事の `img/` のように、道具が決まった場所と名前で読む絵は、`"to": "08_店/<店のフォルダ>/_gen/set-1"` のように置き場を名前ごと書きます**（商品フォルダの中の `_gen/` か `img/` の下だけ。日付は付かず、同じ名前は新しい方が勝つ）。

## 3. ZackDFilms（v1・847 の質感）の絵：18章をアプリで回す

**ZackDFilms の絵コンテ・始めの絵は、`image` ではなく必ず `zackd847` で頼みます。** アプリが、元の環境で品質を出した組み立て（`質感847/通し/最新の組み立て/pipe.py` の build()）と同じ文・同じ見本の絵・同じ段の順で、段0（人物の見本）→段1〜5 を回します。ダルマが自分で段の文を組み立てると、文が少しずつずれて質感が落ちます（2026-10-26 の通しテストで、断面の場面が写真寄りになった）。見本の絵の無い「絵コンテ」の `image` は、アプリが断ります。

```json
{"zackd847": {
  "name": "packA_01_絵コンテ",
  "character": {"age": "mid-50s", "hair": "shoulder-length straight black hair with a few gray strands", "face": "a round, full face with soft, slightly sagging cheeks", "outfit": "plain light-gray cotton pajamas with long sleeves reaching the wrists"},
  "scenes": [
    {"id": "場面01", "type": "medium", "place": "寝室", "content": "A medium shot from a 3/4 front angle at chest height in <場所の文>. Our woman, <人物の文>, ...", "pose": "sitting up in bed, right hand on her throat"},
    {"id": "場面06", "type": "cutp", "place": "寝室", "content": "...", "pose": "..."}
  ]}}
```

- `type`：`medium`（人の中くらい）・`face`（顔の寄り）・`hand`（手の寄り）・`cutp`（人の体の断面・透けた窓）・`cut`（人のいない断面）・`macro`（大写し）・`object`（物と部屋）。構図の見本を替えたい時だけ `comp`（`F21` 夜の青い部屋・`F22` 床すれすれ・`F23` 水色の居間・`F24` 胸の高さ・`A0` 顔の寄り ほか）。
- `content`・`pose` は英語。場所の文と人物の文は、全部の場面で一字も変えずに入れる（18章）。`place` が同じ場面は、前の場面の段1の絵を見本に足して部屋をそろえる。
- 人物の見本（段0）は、`character` が同じなら前に作った物を使う（`07_納品/画像/_段/zackd847.json`）。
- 最大12場面・同時に3場面。1段は1〜15分。途中の段は `07_納品/画像/_段/` に残る。
- 終わりの絵（動画の終わり）は、出来上がりを Image 1 にした「ここだけ変える」の編集を `image`（refs：出来上がり → T10 → T19）で1回（pipe.py の `edit_prompt` の文を写す）。
- 出来たら、1枚ずつ原寸で見る（18-2 の最後）：指・手の数・顔の崩れ・物の位置・袖の長さ・前のコマとのずれ。直す時は、`_段/` のその段の前の絵から `image` の `steps` で、その段だけやり直す。

## 4. ほかの型

- 静止画広告（`ec-static-ads`）・ほかの動画の型（skeleton・clay-story・authority-live）・店（`pdp-tsukuru`）も、手順書が見本の絵を渡すと書いている所は、同じく `refs` で渡します。同梱してある見本の絵は、各手順書が書いている道（`ec-ad-ops/references/static-formats/`・`video-formats/<型>/` など）にあります。
- 商品の写真（18-6 の1）：商品フォルダに1枚置き、`refs` で渡します。無い時は、仮の形で描いたことを報告に書きます。

## 5. 使えない物（正直に言う）

- 動画化（Higgsfield の Kling）・声（ElevenLabs）・編集（Remotion）は、つないだ道具がダルマに渡っている時だけ使えます。無い時は、絵コンテ（始めの絵）までで止め、何が足りないかを書きます。
- 参考画像を渡せない作り方（文だけで描く）に、黙って切り替えない。どうしても渡せない時は、その理由と「質感は手順書の水準に届かない」ことを報告に書きます。

## 5. 動画にする・編集する

絵コンテを動画にする（Higgsfield。お金を使うので承認カード）・編集する（ffmpeg と Python の道具）時は、`_アプリでの動画の作り方.md` を読みます。Remotion は、Remotion での編集を頼まれた時だけです。
