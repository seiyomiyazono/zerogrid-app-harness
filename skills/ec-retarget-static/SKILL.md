# EC リタゲの静止画

読む人: リタゲ（一度来た人・買う直前の人）向けの静止画を作る Claude
読む時: 「リタゲの静止画を作って」「カゴ落ちの広告を作って」「買う直前の人向けの静止画」と言われた時
読まなくていい条件: 新規向けの静止画（ec-static-ads）・動画・記事・店を作る時

**一行で: 相手の今の気持ちから始めて、1枚で疑いを1つ消す静止画を、参考の広告を要素ごとに気持ちごと写して生成する。設計の検査・4:5 の検査・要素ごとの点検を通った物だけを出す。**

このファイルの並び順は意図的（関門 → 参考 → 手順。`skill-creator/references/skill-format.md`）。

実測済みの事実（2026-11-17・18）:

- Meta の広告のコネクタ（`ads_get_ad_entities`・`level` は `ad`）の返事は `{"ad_entities": "<広告の並びを文字にした物>"}` の形で、消化は `amount_spent.value`、購入が0件の広告は `omni_purchase` が空。`scripts/sync_results.py` はこの形のまま読む。
- 画像生成（ターミナルでは アプリの画像作り（`image`）、アプリでは `_アプリでの画像の作り方.md` の `image` に `refs`）は、縦長を頼むと 1024×1536 で返る。4:5 にするには上下128画素ずつを切る。
- 参考の絵と実物の商品写真を添付すると、日本語の字は4枚中4枚が指定どおりに出た。付属品は、写真を添付しなかった物（ベルトの留め具）で実物と違う物が出た。
- 余白を160画素と指定しても、4枚中2枚は絵が上下に寄るか縦いっぱいに出た。`scripts/crop45.py` は切る窓を上下に動かし（1枚）、縦を広げて左右を端の色で埋め（1枚）、4枚とも終了コード0になった。前に字が端から4画素にあった1枚は、今も落ちる（終了コード1）。

測定の限界:

- `scripts/crop45.py` は隣の画素との色の差（合計60より上）を輪郭に数えるだけで、字か背景の写真かを見分けない。写真が背景の絵は落ちる事があり、地の色との差が60以下の薄い字は数えない。落ちたら Read で `_要確認` の絵を開き、字と商品が切れていないかを確かめる。
- `scripts/check_plan.py` は欄が埋まっているかを見るだけで、中身が合っているか（疑いが本当に客の言葉か・気持ちの読みが当たっているか）は見ない。
- 要素ごとの点検（関門5）と字の点検（関門6）は、Read で参考と出来た絵を開いて人の目で当てる。数える道具は無い。
- リタゲの結果は、絵だけで決まらない。その前に出した新規の広告（何を聞かせたか）・オファー・時期・相手の決め方で変わる。そのため結果はこの4つと一緒に残し、同じ商品・同じ時期の結果だけを勝ちとして使う。新規の広告が大きく変わった後の古い結果が、今も当てはまるかは道具では見分けない。
- 出来た絵が売れるかは、配信するまで分からない。見本の数字は `references/枠組み.md` の表のとおりで、消化と ROAS が分かるのは自分の口座の2枚だけ。

</reference>

# 3. 手順（この順。段ごとに関門を通してから次へ）

1. **相手と、その人が新規の広告で聞いた事と、今の気持ちを決める。** `references/枠組み.md` の「落ちた場所ごとの既定」から相手を選ぶ。次に、その相手が通ってきた道を読む: その期間に消化が最大の新規の広告3本と、その飛び先（記事か店）を開き、もう聞いた事を1文で書く。まだ配信していない商品は、`04_初日の出稿設計.md` の最初に出す pack の原稿と着地から書く（リタゲの相手は、新規の広告で温まった人。何を聞いた後かで、残る疑いが変わる）。その上で、何で止まったかを1文で書く。相手の人数（Meta の広告マネージャ → オーディエンス の推定の人数）が100人に届かない店は2つにまとめる。
2. **疑いを1つ決める。** 商品フォルダ（読む所は `references/harness-map.md` の「入力」）から客の疑いの一覧と原文を読み、手順1の「新規で聞いた事」でまだ答えられていない疑いの中から、この1枚で消す疑いを1つ選ぶ。複数枚作る時は、枚ごとに違う疑いを割り当てる。取れない時は既定の疑いを使い「既定」と書く（既定に疑いが2つ並んでいる相手は、1枚に1つを選ぶ）。
3. **起こしたい気持ちと、消す事実を決める。** 疑いが消えた時にその人が思う事を1文で書く（例: 値段の疑い →「今の条件が終わる。今なら得」）。その気持ちを起こす商品の事実を1つ選び、出どころのファイルを書く。
4. **参考を道具に選ばせる。** `references/枠組み.md` の「7つの型と見本」で型を決め、`python3 scripts/samples.py pick <型の番号> --商品 <商品フォルダの名前> --時期 <通常|セール中>` を実行する（時期は、運営者が決めたセールの期間の中なら「セール中」、他は「通常」。`配信の条件.md` があれば、その時期と同じ）。出た1枚が参考（自分で選び直さない）。道具は配信の結果で選ぶ: 同じ商品・同じ時期で勝った見本を先に出し、4回に1回と、同じ条件の勝ちがまだ無い時は試す見本を出し、同じ商品で負けた見本は出さない。他の商品や他の時期での勝ちは、試す見本の中の順番を上げるだけで、勝ちとしては扱わない（リタゲの結果は、その前に出した新規の広告・オファー・時期で変わるため）。出た絵を Read で開く。見た目だけをハーネスの静止画の型（st01〜st10）から借りる時は、この道具を通さず、その見本の絵を参考に書く。
5. **参考を要素に割り、要素ごとに気持ちを書き、起こしたい気持ちを強める要素を決める。** `templates/設計.md` を設計のフォルダ（`references/harness-map.md` の「置き場」）に `設計_<広告の名前>.md` の名前で写し（その商品のリタゲの設計は、前の回の分も同じ `設計/` に置く）、参考を上から順に全部の要素に割る（背景・印とロゴ・最大の字・次の字・出どころの行・区切り・答えの字・商品の大きさと位置・小さい注記）。1行ごとに「相手に起こす気持ち」を書き、4列目に、その気持ちが手順3の「起こしたい気持ち」を強めるかを書く。絵に入るのは「強める」の行だけで、その行にだけ、同じ気持ちが起きる「うちの要素」を書く（字は語尾・句読点・行数・色と書体の差まで。例: 客の声の語尾の「…」は言い切らない本物の声に聞こえるので、そのまま「…」）。参考の店の事情で入っている要素（その店の主張への注記・その店だけの賞や事情）は、起こしたい気持ちを強めないので「強めない」になり、うちの要素は「入れない」になる。書けたら `python3 scripts/check_plan.py <設計のフォルダ>` を実行する。
6. **指示文を組む。** `python3 scripts/make_prompt.py <設計のファイル> --添付 "2枚目=<実物の商品写真の説明>" --添付 "3枚目=<付属品の写真の説明>"` を実行し、出た指示文をそのまま使う（指示文に入る要素は、表の「強める」の行だけ。手で要素を足さない。足したい物がある時は、設計の表に行を足して、もう一度実行する）。
7. **生成する。** 参考の絵と実物の商品写真を添付して縦長で生成する（ターミナルの アプリの画像作り（`image`） は `aspect: "portrait"` と `refs`（添付する絵）。アプリは `_アプリでの画像の作り方.md` の `image` の `refs`）。付属品（ベルト・箱）が写る絵は、その実物の写真も添付する。生成ごとに `設計/生成の記録.md` の表に1行（出す絵・参考の絵・実物の写真・返った大きさ）を書く。出来たら `python3 scripts/crop45.py <生成した絵> <出す絵> --参考 <参考の絵>` を実行する（参考の上下の余白の割合を測って、同じ余白で切る）。「合わせられない」で終了コード1の時は、`--参考` を外して実行する。
8. **点検する。** 関門5〜8を当てる。参考と出来た絵を並べ、要素の表を上から1行ずつ○×で書く。×があれば、その行だけ直した指示で生成し直す。
9. **見出しと本文を書く。** 見出しは27字以内で、この1枚の疑いに合わせる。本文は短い・中くらい・長いの3案。決まりは `ec-ad-ops/references/creative-foundation.md` の6章。時期の言葉とオファー（セールの名前・期限・割引）は絵の主役にせず、見出しと、本文の1行目に入れる（例:「【ブラックフライデー開催中】最大40%OFF＋送料無料」。自分の口座の勝ち広告と同じ形）。6章の「値段と期限は3文目より後の1行」は新規向けの決まりで、リタゲの本文には当てない。
10. **試しの結果を入れる。** 運営者の直しが入ったら、絵を直すだけで終わらせない。`references/試しの記録.md` に「起きた事・原因・止めている所」を1行足し、手順か検査の道具を直す。
11. **納品する。** `python3 scripts/check_plan.py <設計のフォルダ> --納品前` が終了コード0になってから、納品の場所（`references/harness-map.md` の「置き場」）に `画像.png`・`ヘッドライン.txt`・`本文.txt` を置く。設計は `設計/` に置いたまま。参考と出来た絵を並べた1枚を運営者に見せる。
12. **配信の結果を見本に戻す。** リタゲの広告セットの数字を読んだ日（`ec-ad-ops` の毎日の運用の中）に、次の2つをやる。(1) Meta の広告のコネクタで、その期間の広告ごとの数字（`level` は `ad`。`fields` は `name`・`adset_name`・`campaign_name`・`amount_spent`・`omni_purchase`・`omni_purchase_values`。新規のキャンペーンの広告も入れる）を取り、返事をそのまま `<設計のフォルダ>/口座の数字_<日付>.json` に保存する。(2) `python3 scripts/sync_results.py <そのファイル> --設計 <設計のフォルダ> --期間 "<いつからいつ>"` を実行する。終了コード4（結びつく見本が0件）の時は、`配信の条件.md` の「広告と設計」の表に、口座の広告の名前と設計の名前の読み替えを書いて、もう一度実行する。`配信の条件.md` は、配信を始める日に `templates/配信の条件.md` を `<設計のフォルダ>/配信の条件.md` に写して1回書く（オファーか相手を変えた日に書き直す。口座の広告の名前が設計の名前と違う時は、その表に読み替えを書く）。自分の口座で勝った絵そのものは、`python3 scripts/samples.py add …` で、その型の新しい見本にも足す。

</procedure>
