# 商品データの作成・更新用雛形

[EC/CLAUDE.md](../CLAUDE.md) に従い、各自社ブランドフォルダの `01-商品情報.md` に以下を記録する。新商品を扱う時と仕様・価格・条件変更時に更新し、VSL制作前に読む。対象商品固有の値を過去の商品から推測して埋めない。現在欄を置換し、過去の全文は同ブランドの履歴へ保全する。本文は「確定した次回条件（未反映）／検討案」「実販売中の条件・確認記録」「原価・換算前提」「未解決」「昔→今と履歴リンク」に分ける。確定済み未反映と検討案も見出し・状態で区別する。

| 必須項目 | 記録する内容 |
|---|---|
| 日付・状態 | 決定ID、本人確定日、実反映日、最終検収日時と証拠。検討中/確定未反映/反映未検収/検収済み/保留を区別。整理日は実測日と別 |
| 商品 | 自社ブランド、販売名、参考競合名との対応、ユーザーの採用判断。何に使うか、型・構造・手入れ。販売文言と性能実証、採用と研究条件の合格を区別 |
| 販売仕様 | 実際に選べる色・サイズ・実寸・枚数、全variant数、販売しない型 |
| 価格 | 比較元価格、実販売価格（セール時を含む）、登録後価格、固定値引額、実割引率。サイズ/色/枚数による差、比較元の根拠と適用条件を明記 |
| 登録特典 | 訴求、対象商品、登録成功条件、適用単位、利用回数/併用条件、表示と決済の検収 |
| 原価 | 見積の出所・日付、USD等の原通貨、円換算、為替前提、送料込みかの確認状態 |
| 利益率 | 算式と除外費用。原価のみの粗利率を純利益率と呼ばない |
| 配送 | 発送元の表記、送料、注文からお届けまでの日数、仕入納期との整合性 |
| 返品・保証 | 申告期限、使用後/未使用/不良の区別、返金額、返送負担、証拠、処理日数、回数 |
| 特典・主張 | 実ファイルと提供設定、レビュー/数値/性能の根拠。競合情報と区別 |
| 運用・出所 | 販売URL、Shopify商品ID、素材参照先、同ブランドの広告/VSL/台帳.md・出稿設定・運用/結果/判定.md・運用/結果/日次.md・状態.md、検収証拠、未解決事項 |

実価格の正本はこの `01-商品情報.md` だけとし、別の価格横断表を維持しない。共通の算式・訴求基準は `ハーネス/共通ルール/価格・特典.md`、ROAS/CPC/CTR/CPM/AOV等の共通判定基準は `ハーネス/共通ルール/判定.md` を参照する。サイト・カート・checkout・台本で同じ条件になっていることを確認してから反映完了とする。

採用・命名の変更は `EC/台帳.md` へ、VSLの採用・制作・配信の変更は同ブランドの `広告/VSL/台帳.md` へ同じ作業中に反映する。VSL台帳には参考競合名・GetHookd広告IDと参考URLを必須で記録し、`EC/VSL台帳.md` はリンク入口として扱う。関係する正本と実素材へのリンクを検収して作業を完了する。
