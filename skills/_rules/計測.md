# 計測の共通ルール

ブランド固有のURL・project ID・UTM・保存セグメント・検収状態は各ブランドの「運用/計測設定.md」を正本にする。[設定の入口](../計測設定.md)。

- 既存Clarity projectを保全し、同じストアにloaderを重複追加しない。入力の氏名・住所・メールやcart tokenをcustom tag/eventに送らない。入力欄をマスクし、Shopifyの分析同意が許可された時だけ追加イベントを送る。
- Meta広告のUTMはブランドcampaignとVSL番号を付け、広告ID/campaign等は有限の確認済み値だけタグへ反映する。新広告追加と同時に、VSL台帳・UTM・ID対応・保存セグメントを更新する。
- QA URLにはec_qa=1を付け、広告評価用セグメントからQA/previewを除外する。過去の識別子なしテストを完全に遡って排除できると主張しない。
- カート追加ボタンのクリックと、Shopifyへの追加成功を区別する。登録済みフラグと新しい登録成功も区別する。
- 商品PDPの見出しが半分以上表示され、800ms後にも見えている時にsection eventをページ中1回記録する。最後に見た箇所から心理的な離脱理由までは断定しない。

| イベント | 意味 |
|---|---|
| ec_email_popup_viewed | 登録画面表示 |
| ec_email_popup_closed | 登録せず閉じる |
| ec_newsletter_confirmed | サーバー成功を確認した登録成功処理 |
| ec_color_changed / ec_size_changed / ec_pack_changed | 実選択の変更 |
| ec_cart_add_succeeded | カート追加APIの成功 |
| ec_checkout_redirect | 購入画面への遷移開始。注文完了ではない |
| ec_section_*_viewed | 各ブランドで定義した見出しの到達 |

ブランド・live/preview/qa・VSL・広告ID・campaign・placement・色・サイズ・枚数を固定タグとして使う。購入数と売上はShopify、広告帰属はブランド別Meta公式pixel/CAPIで確認する。ViewContent金額を購入売上へ流用しない。Clarity送信受理と管理画面候補への反映を別々に検収する。

ファネルを保存する時は「PDP URL訪問→ec_cart_add_succeeded→ec_checkout_redirect」。登録が購入必須という直列条件を作らない。候補未反映なら、未作成と記録して自動クリックを成功イベントとして代用しない。

テーマ再生成は最新MAINを基点にし、計測hookを最後に適用して読込が消えないようにする。定期監視・永久保存・自動exportは、実際に設定して検証した時だけ稼働中と記録する。
