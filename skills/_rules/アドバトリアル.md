# アドバトリアルの形式選択と制作

**読みやすさの基準（2026-09-26本人承認・全記事で毎回）**：対象は50〜60代、小学6年生が一度で分かる文で書く。専門家の一人称（「こんにちは。獣医師の◯◯です」）と気づき型の冒頭、当てはまりチェック3つ、各節末の次への一行、1文短く・読み仮名・専門語の言い換え、図解は同じ絵柄で統一、価格は1節でおすすめ1セット、病院への誘導は書かない。今の記事の入口は [article.md](ec-ad-ops/references/article.md)。

**現在の判断基準・2026-09-17本人指定**：制作前の「このVSLなら何のadvertorialがいい？」という相談から、次の順で説明する（今の型選びは [_VSLから型を選ぶ.md](ec-ad-ops/references/article/型/_VSLから型を選ぶ.md)）。VSLで伝わること→残る疑問→LPで答えられるか→記事の追加価値→使える材料と推奨形式・内容、の順で説明する。Founder’s Storyは開発経緯が商品の違いを説明できる場合に候補とする。認知段階や尺だけで記事を必須化しない。統合制作・承認手順は [flow.md](ec-ad-ops/references/flow.md)。以下の参考再現・既存承認を維持し、相談を制作や公開の許可に読み替えない。

**専門家型の節内配置（2026-09-12追加）**：試用は対象と悩み→時点ごとの反応→再診の言葉、特徴は医師への質問→箇条書き→引用→写真という順序まで参考に合わせる。

**コメント欄（2026-09-12本人指定）**：最初の購入前の質問に、購入・使用経験の返信が続く並びを基本にする。まとめ買い・使用感・気持ちの変化などを一人一論点へ分ける。商品ごとの原稿は各記事の制作資料。

2026-09-06 運営者指定。ECハーネスの制作工程を拡張する。これは運営者の基本制作ルールであり、マーク本人の発言として扱わない。

**ローカル制作の進め方（2026-09-12追加訂正）**：実話・人物確認をローカルHTMLの制作開始や納品の条件にしない。本人が設定を任せたらこちらで入れて完成させる。記事中の「構成確認用フィクション」「仮台本」「仮設定」等は不要。設定と素材の記録は制作資料へまとめる。写真制作を指定されたら、過去の画像枠指定で止めず、実物参照を使って生成する。

**現在の制作入口**：（旧。2026-09-12 の「形式が未指定なら Miro の6形式から選んでもらう」は、今は [article.md](ec-ad-ops/references/article.md) と [_VSLから型を選ぶ.md](ec-ad-ops/references/article/型/_VSLから型を選ぶ.md) で型を決める＝bakuro-copy・listicle-copy・ranking-copy・quiz-jp-copy）指定済み・参考指定・改稿は引き継ぎ、委任された場合は選んで進む。以前の別案件の委任は新しい依頼の形式選択を省く理由にしない。本数未指定は1本。VSLは前段広告として分析し、VSLだけの制作に記事の形式質問を追加しない。

**専門家型**：権威性・原点→未解決の悩み→専門的理由→試作・商品化→動機回帰を維持する。他商品では人物・専門分野・因果・仕様・証拠を適切に差し替える。6形式全部に家族や医師の物語を押し付けない。

今回と同じ型確認出力では、本文をこちらで埋めたHTML＋説明入り画像枠を先に納品する。人物設定を任された箇所は、こちらで全文を埋める。制作注記は記事へ出さない。画像は本人の最新指定に従う。承認は形式・読み味・分量・デザインの制作見本としての評価であり、架空の監修・取材・試験の事実認定、公開・広告送客の承認、CVR実証ではない。

**2026-09-12・節の分量と意味まで再現**：参考のセクション別本文文字数・段落／箇条書き数を実測し、自社版も同程度に揃える。全体字数だけの照合で済ませない。原点の節で従来策に残る問題を示す→次節で専門的な理由を平易に説明する→試作と製品化、の読み進める順序を保つ。登場人物の一人ずつに複雑な役割を重ねない。

**2026-09-11・人物記事の訂正**：専門家の原点・家族や診療の背景→未解決の問い→発見→動機への回帰を持つ参考は、その物語を再現する。肩書だけのQ&A・選び方記事へ置き換えない。明確さに加えて、ヘッドラインには読み進めたくなる具体的な疑問を置き、本文と結びで回収する。売るためだけの人物にせず、なぜ伝えるかを原点とつなげる。

型を確認するHTMLでは、人物・家族の仕事・きっかけ・会話・動機までこちらで一貫した仮設定を入れる。実話を聞き直して本文を空欄にしない。制作注記の置き場と画像の扱いは9/12の最新指定を優先する。仮設定を実在の推薦や開発実績に昇格しない。医療効果は創作しない。今回の専門家型は権威を使う指定を維持する。

制作見本の承認と、各記事の現在の公開/送客状態を分ける。最新段階は各ブランドの `状態.md`。

## ARUKOTO形式を再現する場合の補助手順

[記事の今の入口（article.md）](ec-ad-ops/references/article.md)を制作開始と納品前に読む。現在の選択形式と統合手順を優先する。

- 手順は、前段VSLと商品データの確認→顧客のペイン→参考の実測→見出しだけで流れ確認→一節一要点と具体的理由→用途別画像→保証と生活への締め→下部オファー→スマホ実描画→納品・台帳更新。
- 文章量は短い結論だけで終えず、場面・理由を少し添える。全商品を同じ文字数に固定しない。
- 画像は役割を決め、GPT Image 2へ複数角度の実物参照と構図参照を渡す。形と寸法感、清潔な画作りを基本とし、本人添付の最新版指定を優先。既存の選定画像や動画を理由なく生成し直さない。
- スマホの主見出し28〜34px／補足21〜24px／本文16pxを今回の再現目安にする。意味で改行し、文字を覆わない下線と十分な余白を確認。数字・保証・色を他商品へコピーせず、商品データに合わせる。
- 実証や公開状態は完成承認とは別に保持する。

## 顧客のペインと明確な言葉（2026-09-06 最新訂正・上記の各5案指定に優先）

- クレバーさよりクリアさを優先。「してくれない」は「おしっこしてくれない」、「盲点」は文脈に応じて「理由」など、主語・行動・意味が一読でわかる言葉にする。
- 全商品で先に「本人がつらい場面／その気持ち／望む生活」を顧客の言葉で定め、既存対策で残る悩み→商品が応えられる点→根拠をつなぐ。仕様・選び方・見つかった研究から主題を逆算しない。本人指定・VSL原文・顧客発言とエージェントの仮説を区別する。
- 今回の失敗は、研究の比較項目から「選び方がわからない」を中心的ペインにしてしまったこと。選定基準は解決の説明に使い、顧客が最も嫌だと感じることの代わりにしない。
- 各1案の冒頭一式（見出し・括弧文・呼びかけ・短い説明）は承認済み。以後は文面を固定して記事制作。
- 権威は中心ペインに関係する出典で支える。実在の専門機関の紹介・研究を、その機関が自社商品を開発・監修・推薦・効能実証したかのように転用しない。
- 追加訂正：ヘッドから冒頭の締めの文までに自社商品名を絶対に出さない。商品カテゴリと仕組みで興味をつなぐ。

## 入力と分析

1. 対象ブランドの最新の商品データ、広告/VSL/台帳、各広告のヘッドライン・投稿本文、制作済み日本語台本と元動画の文字起こしを読む。視聴者が受け取る内容の判定は完成日本語版を優先し、元動画と差がある箇所を区別する。図解・実演など文字だけに出ない説明は映像でも確認する。
   最新広告分析も取得し、取得時刻・分母・配信初期の母数不足を明記する。クリック率だけで勝ち記事を断定しない。商品JSONとPDP・ポリシーを再確認し、正本と不一致なら記事で都合のよい条件を新たに約束しない。
2. 広告ごとに、顧客の悩み・不安／悩みの原因／従来策の限界／解決の仕組み／解決策を選ぶ基準／証拠／使い方と適用範囲／購入前の疑問と条件を表にする。
3. 各項目を「なし・言及のみ・理由まで説明・証拠や実演まで説明」で記録し、台本の該当箇所・時刻と根拠を付ける。これは説明の厚さの整理であり、CVR予測スコアではない。文字数やキーワード出現だけで濃淡を決めない。
4. 表の各行に「記事では短く確認／詳しく説明／不要」と理由を付ける。商品性能や原因について根拠がなければ、説明を創作せず確認事項にする。

## 広告と記事と商品LPの役割

- **記事単体で読んでも理解できる。VSLの全編視聴・理解を前提にしない。** ただしVSLが深く説明済みのことを、記事でも同じ長さ・同じ展開で繰り返さない。要点を短く受けて次の疑問へつなぐ。
- VSLで薄い原因・選定基準・不安の解消を記事で厚く書く。広告の約束に答え、商品を選べる理由をつくる。説明の固定比率、固定文字数、商品を出す固定位置より、実際の前段広告と必要な理解を優先する。
- 商品LPへ渡す時点で理解してほしいことと、LPに任せるサイズ・色・セット・価格・配送・保証・注文操作を明記する。記事内にも判断に必要な条件を簡潔に示し、「重複禁止」を理由に必須情報を消さない。
- 未解消の疑問が商品LPだけで十分扱える広告は、PDP直行の候補として理由を示す。全広告へ機械的に記事を挟まない。既存の配信先変更は、具体的なページ・広告対応表を用意してから承認範囲を確認する。

## 共通記事か個別記事か

| 広告間の違い | 記事の扱い |
|---|---|
| 対象顧客・悩み・約束・仕組み・残る疑問が共通 | 共通記事を使う |
| フックや使用場面だけ違い、教育本文は共通 | 導入だけ差し替える |
| 原因の捉え方、選ぶ基準、商品への期待、解消すべき不安が実質的に違う | 別記事にする |

広告1本につき記事1本を固定ルールにしない。広告番号→記事ID→共通／導入差分／別記事の理由を対応表に残す。これは実際の台本を分析して決定し、未分析の18本を分類済みと報告しない。

- 記事は ec-ad-ops の [article.md](ec-ad-ops/references/article.md) とその先の型（bakuro-copy・listicle-copy・ranking-copy・quiz-jp-copy）で作る。このEC指定が汎用Skillの固定比率・商品遅出し・型ごとの強制分割と衝突する場合は本指定を優先する。ユーザーが委任した型や分割判断を聞き直さない。

- 未承認の外部例は参考候補として保持し、承認済み教材へ自動昇格しない。参考のレビュー・体験談・性能数字は忠実に使い、原文由来である事を制作資料に記録する（[広告.md](広告.md#static-ads) と同じ扱い）。価格・割引・特典・期限は自社条件へ合わせる。
- 2026-09-06の最新指示で制作を委任されたため、参考選択を聞き直さず、文字起こし分析→広告別の対応表→記事構成・原稿→ページ制作・検収へ進む。既存VSLの台本・音声を記事制作の都合で変更しない。
- 差し込み画像・基本の商品イメージは **HiggsfieldのGPT Image 2** を使う（運営者指定）。商品写真を参照し、形状・カラーを確認する。生成した生活・説明画像と実物写真を区別する。VSLへ新たに画像を差し込む場合も同じ方針だが、今回の依頼で既存完成VSLを無断で再編集しない。
- 納品先は各ブランドの `広告/アドバトリアル/`。台帳に記事ID、対応VSL番号、参考URL、完成ファイル、公開URL、制作/承認/公開状態を記録。各記事フォルダに最新版のみ、旧版は `_過去版/`、分析資料は `_制作資料/`。空の完成記事や未採用参考を制作済み台帳へ登録しない。
- 公開時には広告ID/UTMを商品LPまで引き継ぎ、記事訪問→商品LP→カート→チェックアウト→購入の分母を区別して検収する。既存の計測を保持し、記事クリック率だけで採否を決めない。分析は俺らの基準・マークの基準・エージェントの意見を分ける。

## 承認に至った修正パターンを、次の商品へ適用する

1. 具体的な場面と動作を書き、本人がいちばん嫌だと感じる気持ちを定める。
2. 既存の対策で残る問題と、望む生活を一文で結ぶ。見出しで開いた疑問にサブで答え、別の問題へ飛ばない。
3. 商品名は伏せても、そういう商品があることは隠さない。どういう仕組みの商品かまで具体化する。
4. 権威は確認した出典の射程内。専門機関によるカテゴリ紹介と、自社製品の監修・推薦・性能実証は別。
5. 承認された部分は固定し、訂正された部品だけを修正する。
