# サイトルール
更新: 2026-09-03

## 何を作るか
参考サイト(競合)を**HTMLで完コピ**し、Shopifyに差し込んで**ちゃんと動く状態**にする。

## 手順
1. 参考サイトをHTMLでそのままコピーする(定期購買の仕組みも含めてそのままコピー。消すかどうかは運営者が最後に見て決める)
2. 日本語化する。不自然な日本語にしない
3. 商品画像: ブランド名が入っていれば差し替える。パッケージはサプライヤーに確認し、違えば**同じ構成でパッケージだけ変えて作り直す**(Image2)。パッケージが写っていなければ翻訳だけでよい
4. レビュー: 顔を日本人風に差し替える(Image2)。内容はそのまま使う
5. 特商法・法務ページ: **欄だけ作る**。中身は後から運営者が入れる
6. Shopify: API接続を自分で通し、指定されたストアにHTMLを差し込む
7. 動作確認(下の検収)

## 決め方
- **ブランド名**: 商品確定後に運営者が指定する。ストア名はそれをもとに決める
- **ストア**: 商品データ・出稿設定の本人指定を確認し、未指定の時だけ確認する
- **価格**: 原価・為替から試算し、[価格・特典](価格・特典.md)と対象商品の商品データにある本人確定を使う。初期の粗利目安で最新の確定価格を再計算・上書きしない
- **構成**: テスト段階は**単品+セット**。定期購買は後から追加(コピー自体はしておく)

## 検収(案・ここは実装時に運営者と詰める)
- 全リンクが自ストア内で生きている
- 購入ボタン → カート → チェックアウトまで実際に操作して通る
- 英語が残っていない
- スマホとPCの両方で崩れていない
- 売っていない商品・存在しない価格が見えない

## 納品物(EC/<番号-商品名>/運用/ウェブサイト/)
- HTML一式(そのまま開ける)
- プレビューURL
- 検収結果.md(上の項目ごとに証拠)
- 差し替え表.md(画像・レビュー・文言の前後)

## 日本語化の規格(2026-09-04 運営者の検品フィードバックで確定)
- **直訳禁止。** 辞書置換の日本語をそのまま出さない。意味を保ったまま、日本のDTCサイトとして読みやすく分かりやすい日本語に書き直す。通し読みで不自然な文がゼロになるまで直す
- **海外仕様は全部日本仕様にする。** 日本向けストアなので、読んだ人が「海外のサイトの翻訳だ」と気づく要素を残さない
  - 人名(レビュー投稿者・体験談の語り手・創業者ストーリーの登場人物)は日本人の名前にする。年齢層と性別は元のまま
  - 犬・猫の名前は日本の犬猫っぽい名前にする(モモ・ハナ・ココ・そら・まる・レオ・チョコ 等)
  - 単位はメートル法だけ: インチ→cm、ポンド→kg、°F→℃、オンス→g/ml。サイズ表・寸法・耐荷重も全部換算する。「インチ」という語を残さない
  - 地名・州・国・「アメリカで◯万人」のような統計は、自店の確認済み事実に合わせる。発送元を日本・東京・国内倉庫と推測で置き換えない。発送元はユーザーの最新指定に従う。日本の統計は調べて置き換える
  - 通貨は原価が確定するまで$表記のままでよい(価格はサイト.mdの「決め方」で確定してから円にする)
- レビュー・体験談の**中身(出来事・感想)はそのまま**訳す。変えるのは名前と単位と地名だけ
- 納品時は `文言対訳.md` に 英語→日本語(改訂後) を全件残し、`差し替え表.md` に差し替えた人名・犬名の対応表を残す

## ブランド差し替えの規格(2026-09-04 運営者の2回目検品で確定。次回からは最初からここまでやる)
- **商品名が決まったら、この順で1回で通す**: ①ロゴ生成 → ②ロゴや英語文字が入った画像の作り直し → ③文字のブランド名置換 → ④レビュー・体験談の顔写真を日本人に → ⑤海外前提の金額訴求を円に → ⑥本家だけの約束(寄付・受賞・監修等)を削除
- **ロゴ**: 本家ロゴを参照画像にして、同じテーマ・同じ色・同じ書体感で文字だけ日本名に置き換えて生成(ピンクならピンク)。道具はHiggsfield(Image2=`gpt_image_2`、CLI `higgsfield generate create gpt_image_2 --image <本家ロゴ>`)
- **画像**: ロゴや英語文字が入った画像(保証バッジ・比較図・実績帯・パッケージが写る物)は本家画像を参照にして「構図・色・要素は同じ、文字だけ日本名/日本語」で生成し直す。商品本体にロゴが無ければ商品写真は触らない。生成物は必ず目で確認し、文字化け・欠けは最大3回やり直す
- **顔写真**: レビュー・体験談に写る外国人は、本家写真を参照に同じ構図・年代・表情の日本人に生成し直す。名前は自然な日本人名にそろえる。本文は変えない
- **金額**: 「月$60節約」のような比較訴求は、日本の実勢価格(Amazon/楽天の売れ筋で実測・出典を残す)で円に組み直す。自社商品の絶対額は価格確定まで書かない(「洗って何度でも」等の書き方にする)
- **本家だけの約束**は削除する(売上の◯%寄付、受賞、監修など私たちが担保できない物)。やるなら戻せるように判断待ちに書く
- 納品物: 生成した画像は `ウェブサイト/画像/` に置き、`差し替え表.md` に本家画像→生成画像の対応と「差し替え済み/未達」を書く。本家と並べた比較スクショも残す

## 3回目検品で確定した規格(2026-09-04。次からは最初からここまでやる)
- **色・サイズのバリアントは本家どおり完全再現する**: 色を選ぶと画像が切り替わる仕組みまで含めて再現し、画像は自社の商品(サプライヤーの実物写真)に差し替える。本家のロゴが写っていれば自社流に。売らない色・サイズ(小さすぎる等)は消す
- **商品本体・パッケージにロゴが無い商品には、生成画像でもロゴを入れない**。無地の通常パッケージのまま。サイズ表記だけ
- **円価格**: 為替の観測日時・仮定を明記し、サイズ別価格・末尾・粗利目標は対象の商品データを参照する。旧「サイズ一律」の指定を全商品へ強制しない。反映保留なら価格設定を変更せず、公開時は採用された円額と購入実額をそろえる
- **本家だけの特典(「本日限り3つの無料特典」等)は削除**する。実物が無い物を約束しない
- **生成する人物写真はスマホで撮ったような画質にする**: 高画質すぎるとAIに見える。きれいだが高解像度すぎない、カメラで撮ったような自然さ。顔は買う層(日本人・その商品の年代)に合わせる。動画で再現できない背景は静止画にして、その上に保証バッジ等を重ねる
- **1商品で回す店**: メニューは下の「Shopifyに載せる時の共通仕様」のとおり、「ブランド名(=商品ページ)」と「お問い合わせ」の2つ（2026-09-05確定）。人気商品・セット一覧・アウトレット等の区画は残してよいが、並べるのは自社の1商品だけ
- **本家へのリンクを1つも残さない**(本家へ飛ぶリンク・押しても反応しない要素をゼロにする)
- **本家がカラー混合セットを売っている場合**は、自社の色でセット内容を具体的に組み直し、スウォッチ・説明・画像を合わせる
- 修正指示のスクショで「重なって見えない」と言われた要素は、上に余白を足して画像の上に出す(重ねない)

## 実行時JSで描き直すページの扱い(2026-09-04 改訂3の教訓)
- Replo等の**ランタイムJSがページ全体を本家の部品ツリーで描き直す**サイトでは、HTMLの初期表示だけ差し替えても描画後に本家の写真・英語・リンクに戻る。**バンドル(JS)自体を取り込んで自前ホストし、部品ツリー側も書き換える**
- 検収は必ず**描画後のDOM**で行い、外部読込(本家CDN・本家JS)が0であることを確認する。初期HTMLのgrepだけでは合格にしない
- 下着姿など生成できない写真(NSFW判定)は、本家写真のローカル化で凌ぎ、判断待ちに「サプライヤー実物写真か運営者撮影で差し替え」と書く。構図を勝手に変えた場合は必ず報告する

## 商品画像ギャラリーの規格(2026-09-04 ワンドライ4回目検品で確定)
- **本家のギャラリーと1枚ずつ対照表を作る**(1枚目=◯◯の写真、2枚目=◯◯の動画…)。順番・枚数・種類(画像/動画)を本家に合わせる。クローン側で勝手に増減・並べ替えしない
- **動画は本家のものをそのまま使う**(作り直さない・静止画に置き換えない)。ロゴや英語が焼き付いていても、まずはそのまま。差し替えが要る動画は判断待ちに書く
- **英語の説明画像はロゴを消してデザインそのままで日本語版を作る**(構図・配色・レイアウトは1:1)
- **色を選ぶと切り替わるのは本家が切り替えている画像だけ**。本家が色に連動しない画像(共通の説明画像・動画)は、どの色でも同じ物を出す
- レビューの絞り込み(星・キーワード等)がある場合は、**絞り込みに合わせて表示内容が変わるところまで結線**する

## 商品ページはセクション単位で本家と1:1(2026-09-04 4回目検品で確定)
- **セクションの順番を本家と同じにする**(購入ボックスの位置、説明・保証・特典・FAQ・レビューの並び)。順番が違うだけで別サイトに見える
- **各セクションのデザイン・使っている画像・書き方まで揃える**。本家が画像を使っている所(保証バッジ等)で自作のテキスト組みにしない
- **本家にあって自社に無いセクションを落とさない**(無料特典・保証・比較・FAQ)。実物が無い特典は消してよいが、消したら判断待ちに書く
- **割引表示とセール帯を本家どおり再現する**(定価に取り消し線 → 販売価格、セール名の帯、カウントダウン)。円に直す時も割引率は本家に合わせる
- **実行時JSで英語が一瞬出る(フラッシュ)のは不合格**。バンドル側の初期値も日本語にして、描画の最初から日本語で出す

## 参照URLの固定(2026-09-04 参照ページを取り違えた事故)
- **完コピの参照URLは、着手時に運営者が見ている実物のURLで固定し、`検収結果.md` の先頭に書く**。以後の「本家と一致」の検査は必ずそのURLに対して行う
- 参照URLの決め方: **競合広告の着地先(GetHookdの `landing_page`)を正とする**。同じブランドが「本体ドメインのLP」と「shopサブドメインの商品ページ」の2種類を持っていることがあるので、どちらを写すのかを最初に確定する

## Shopifyに載せる時の共通仕様(2026-09-05 確定。毎回この形にする)
（2026-11-19注記：店（PDP・商品ページ）を新しく作る時の形は `pdp-tsukuru` スキルが正。この節は、参考サイトを完コピしてテーマ標準(Shrine)へ載せる時の仕様）
- **ヘッダーとフッターはテーマ標準(Shrine)を使う**。クローン側の自作ヘッダー・バナーは**消す**(二重にしない)。テーマ標準のロゴを自社ブランドに差し替え、カートボタンとハンバーガーはテーマ標準のものをそのまま使う
- **ハンバーガーのメニューは2つだけ**: 「ブランド名(=商品ページ)」と「お問い合わせ」。ホーム・カタログ・注文追跡・前の店の商品など他の項目は全部消す。**ソーシャルメディアのアイコンも消す**(ヘッダー内・フッター内とも)
- **フッター**: コピーライトのブランド名を自社名にする。ポリシーの欄(プライバシー・返金・利用規約・配送・連絡先・特商法)は**残して中身を自社のものにする**
- **フッターの装飾と配色は毎回ブランドカラーに合わせる**(波などのアニメーションを含む)
- **ポリシー本文の雛形は自社の既存店を正とする**(2026-09-05時点: ワンドライ https://otonagi.shop/products/wandry ・ストアパスワード `wandry-build-2026`)。**内容はほぼそのまま**流用し、店ごとに違う所(保証日数など)だけ書き換える

## 納品前のチェックリスト
Shopifyに載せ終わったら、毎回 `_rules/ストア検収チェックリスト.md` を上から全部確認してから納品する。1つでも×なら納品しない。

## 分割HTMLとスマホの操作（2026-09-05 ワンドライ修正の再発防止）
- **分割前の本文と、全スニペットを順番に連結した本文が一致することを検査する。** 境目を同じ文言の検索で推測しない。余分な閉じタグでCSSの適用範囲から後半が外れるため、購入ボタン・保証・比較・写真・FAQがすべて本文ルート内に残っていることも描画後のDOMで確認する。
- **ページ全体の横幅だけで合格にしない。** 375/390/430pxで保証・送料・日数・費用比較の文字の左右端と折り返しを確認する。nowrapとoverflow:hiddenで文字切れを隠さない。
- 写真カルーセルは指のスワイプと矢印の両方で先頭から最後まで確認。画像の読み込み、枚数表示、端のボタン状態を検査する。移動先と現在枚数の計算はCSSのスナップ位置に合わせ、700px前後でも確認する。
- FAQは質問と回答を区別し、タップ・キーボードで開閉できる形にする。標準のdetails/summaryを優先し、全回答が初期表示されたり長い回答が途中で切れたりしないことを確認する。

## 配送・保証の共通指定（2026-09-05 運営者確定）
- どのストアでも配送の案内は、通常ご注文からお届けまで2〜5営業日。発送準備日数を別に足して長い日数にしない。遅延時は5営業日を過ぎた時点で連絡可能にし、20日・30日間は対応しない等の旧案内を残さない。
- 初期不良・機能不具合（輸送中破損・誤配送も）は到着から7日以内の申告。お客様都合の返品と満足保証の日数は、ブランドの `01-商品情報.md` と店の返品・返金ポリシーが正。返金処理は返送品の受領確認後、返送不要なら対応決定後、7〜10営業日。
- 販売会社の所在地と倉庫の発送元を混同しない。返送先の国は、指定されていなければ推測しない。発送元の書き方はブランドの `01-商品情報.md`。
- 商品ページ、FAQ、画像内の保証日数、カート、/pages、Shopify標準/policies、お問い合わせ/規約リンクを同じ条件へ揃える。未使用都合返品50%控除等の既存の金額条件は、この日数変更では変えない。

## 配信中のファネルだけを差し替える場合（2026-09-06）
- 「価格・カラー・割引をそのまま、構成だけ変更」の指示では、競合側の販売条件をコピーしない。着手前に現行MAIN、全バリアントID・選択肢・価格・比較価格・商品状態・templateSuffixを取得し、完成後に一致を検査する。
- 配信中の現行MAINを複製した非公開テーマで制作する。同じ商品テンプレートを複製側だけで差し替え、ACTIVE商品の設定や広告URLを変更せずにプレビューできる形を優先する。
- 途中の購入CTAは実際の選択欄へ結線する。参考元のランタイムJSを除いた場合は、写真・FAQ・サイズ表の操作を自前で結線し、実タップで状態変化を確認する。
- 既存の登録特典と購入処理を引き継ぐ。計測イベント名・広告識別を維持し、セクション位置が変わる場合は到達セレクターも更新する。QA/previewを実績集計から除外する。
- 保証の運用資料があっても、切り替え前には公開中の正式ポリシー本文を再取得する。商品ページと正式ポリシーの矛盾を見つけたら、ドラフトの検収記録とブランド状態へ残し、公開条件が整った扱いにしない。

## ファネル再現で変更してよい範囲（2026-09-06・9055初稿への訂正）
- 「内容と構成をそのまま、自社に必要な部分だけ変更」は、レビューを一般的な商品説明へ変更する許可ではない。冒頭の短評、長い体験談、ステップ説明、特徴、FAQの役割と順番を維持し、変更理由を差し替え表へ残す。文言の省略・要約が必要な場合は、黙って同等扱いせず本人へ明示する。
- CTAはブランド名を置き換え、元の内部HTML・中央寄せ・幅・余白・セクション内の位置を保つ。ボタンをclearして裸の文字列にすると元の文字用CSSが失われるため、ラベルのテキストだけを置換する。
- 人物はHiggsfieldで元と同じ構図・年代・表情の日本人風画像へ。商品・手順の画像は指定どおり保持する。img.srcだけでなくpicture/sourceの全srcsetを確認し、スマホだけ元人物が残る事故を防ぐ。
- レビューの出所、仮名、生成された人物画像を制作記録で追跡する。参考レビューを自社購入者の検証済み実績と混同しない。参照元の家族経営・顧客数・素材比率などは自社の確定事実へ自動変換しない。
- 「購入欄は既存でよい」と指定されたら、その購入欄を保存し、変更後とHTML・全バリアントの一致を検査する。見た目の最終比較は390pxと1440pxで実施し、翻訳・人物・自店オファーによる差と、修正すべき配置差を区別する。
