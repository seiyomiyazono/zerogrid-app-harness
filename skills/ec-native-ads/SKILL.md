# ec-native-ads — ハーネスの商品フォルダ→長文ネイティブ広告

> **この版の成り立ち（2026-10-07 運営者 指定）**：`native-ads` をそのまま複製し、Phase 0・1（商品理解と診断）を「販売ページを自分で読む」から「ハーネスの商品フォルダを読む」に付け替えた。対応表は [references/harness-map.md](references/harness-map.md)。文体・骨格・鉄則・品質ゲート・参考資料は元のまま。

作るもの: **1広告 = ヘッドライン(本文と別枠・出稿設定用) + 一人称の長文本文(600〜1300語 / 日本語800〜2600字) + P.S. + P.P.S. + CTA + スクロールを止める画像1枚 + LP形式の推奨**。
ブランドが売る文ではなく「体験した人・詳しい人が一人称で語る」文で、LP到着前に信念シフトを済ませるのが目的。
土台はKonvert Native Ads講座(承認済み)+Hookd実測(Chris Walters系、未承認)+**運営者直伝の実戦ルール(2026-08-15 と 2026-08-29 の2本、（同梱していない添削の記録） — 承認済み・最上位。後の日付が優先)**。

## 発動条件

- /ec-native-ads、または `<商品名>/` がある商品で「ネイティブ広告」「native ads」を含む制作依頼
- ec-ad-ops の初日の出稿設計（04）で、pack にネイティブ広告の枠がある時
- ハーネスに商品フォルダが無い商品は対象外
- 対象外: リサーチのみ(→ec-research)、動画広告(→台本は vsl-script、映像は ec-ad-ops)

## モード(2026-08-17新設)

- **通常モード(既定)** — 下のPhase 0〜4。診断リサーチ→オリジナル3案
- **完コピモード** — 運営者が「勝ち広告を写して」と指定したとき。勝ち広告の骨格・型・画像の構図を写し、本文は日本語で書き下ろす。手順は `references/clone-mode.md`

## 工程

**Phase 0 — ハーネスを読む**（[references/harness-map.md](references/harness-map.md) の1章の順で全部）。販売ページを自分で読み直さない。**先に `01_商品理解の基盤/H_根本原因.md` を読む。無ければ書き始めず、ec-ad-ops の root-cause.md で先に作る。** どの pack（層 × 試した物）向けかを `04_初日の出稿設計.md` と F から決める（指定が無ければ、04 の順で最初の pack）。**市場は JP**（ハーネスの商品は日本向け）。**UMシート**: 問題側UM＝H の根本原因の名前をそのまま（別の名前を作らない）、解決側UM＝E の「他にないもの」と仕組みの名前（I_仕組みの細部 があれば、部位の名前まで）。解決側UMが立たない時は、納品物の先頭で警告する。ハーネスに無い事実は「無い」と書き、運営者 に聞くのは最後に1回だけ。

**Phase 1 — 診断シート**。`references/copy-structure.md` のテンプレを全欄埋める。**どの欄をハーネスのどこから埋めるかは harness-map.md の2章。** 採集語彙15〜20個は B ④・⑤ の原文から番号つきで抜く（外へ採りに行くのは、B に足りない時だけ。採った物は出どころを書く）。Q5（原因ではないと思っているもの）＝H の根本原因。Q2（試して失敗した物）は、その pack のヴィランを主役にする。語彙が足りないまま進める時は、納品物に「語彙未採集」と明記。

**Phase 2 — 実例調達**。**JP案件のEXAMPLES第一候補は `references/knowledge/negirai-swipe.md`(運営者提供のお手本。文体・構成の最上位基準)**。加えてHookd MCPが使えるなら `search_ads`(同ニッチ+min_ad_copy_length=1500+run_time長い順)で長文の当たり2〜3本を全文取得。EN実例は `references/knowledge/chris-walters-analysis.md`。選定基準: 同じ語り手タイプ・同じ認知レベル・同じトーン・近い長さ。

**Phase 3 — 生成**。**書く前に `（同梱していない添削の記録）`(1本ずつ添削して合格を出した5本の直し方。最優先)と `references/knowledge/nemuria-good-3.md`(運営者判定「良い」の実物3本)と `references/knowledge/good-bad-diff-otonagi.md`(良い版/悪い版の対照)を読み、リズムを耳に入れてから書く**。`references/mega-prompt.md` の4入力(RESEARCH/STORY/PRODUCT/EXAMPLES)を全部埋めて**3案**書く。3案は認知レベル対応表(`references/hooks-closes.md`)から**フックのメカニズムを変えて**割る(例: Solution Awareなら 定番否定/権威の限界点/専門家超え)。本文骨格は `references/copy-structure.md` の**14ビート(P.S.とP.P.S.まで含めて1本)**。ヘッドラインは本文と別枠で作り、その案が刺したいペインをそのまま名指しする(下の鉄則のヘッドラインの行が正)。

**Phase 4 — 品質ゲート**。**まず `node scripts/copy-check.mjs <納品ファイル>` を回し、「合格」が出るまで直す**(発明比喩・司会進行・記号箇条書き・売り手口調・案間の重複を機械判定。目視は品質保証にならない)。そのうえで全案を6原則(ペーシング/対比/感情順序/ループ/割り込み/信頼の階段)+失敗パターンでチェックし、`references/mega-prompt.md` の修正プロンプト語彙で直す。必須チェック: 商品名が本文55%より前に出ていないか/開けたループを全部閉じたか/**主語落ちが無いか**/**だ調の断片が混ざっていないか**/**専門語を出しっぱなしにしていないか**/クローズでトーンが急変していないか。※クローズのフック回帰は2026-08-29に不要化。

**Phase 5 — 画像**。各案に1枚。**第一基準はスクロール停止力** — 当事者が「うわっ」と手を止める違和感・キモさ(症状部位のマクロ等)を優先し、静かな記録風は停止力が出ない時の次善(`references/native-image.md` の優先順位)。生成は **Codex 内蔵の imagegen**（ハーネスの決まり：絵に Higgsfield を使わない）。プロンプトは ec-ad-ops の `references/realistic-image.md` の型（スマホで撮った1枚・共通の枠）に、`references/native-image.md` の決まり（停止力が先・文字なし・当事者の視点）を重ねる。綺麗に作らない。検収は**停止テスト(1秒で「うわ、それ私だ」が起きるか)→Redditテスト**の順。

**Phase 6 — 納品**。案ごとに headline/本文/CTA/画像/着地（04 のとおり。ネイティブ広告の着地は advertorial＋native 用が基本）をMarkdownで、`<商品名>/06_原稿/native_<pack>_<日付>.md` に置く。先頭に「どの pack 向けか・根本原因・ヴィラン・使った原文の番号」を1行ずつ。承認の後に `07_納品/Native Ads/<pack>/`。末尾に変数(未採集語彙)を明記。

## ハーネスとそろえる事（2026-10-07。下の鉄則より先に読む）

- **根本原因は H の1つ。名前も同じ言葉。** VSL・静止画と別の原因を言わない。メカニズムの伝聞（3〜5文・要素2つまで）は H の仕組みと I の細部から書く
- **ヴィランはその pack の1つを主役にする。** 購入遍歴でほかの物に触れてよいが、主役は変えない
- 呼び名・言わない事・使ってよい人物・保証や在庫で言える事実は `05_原稿の決まり.md`

## 鉄則(運営者フィードバック2026-08-15で追加。破ったら品質ゲートで差し戻し)

- 金額（価格・割引）は、本文に入れてよい（2026-11-19 運営者。8月の「金額は絶対に入れない」は外した）
- **比喩を発明しない(2026-08-23。文章が「綺麗じゃない」と差し戻された原因)**。比喩は**読者が実際に体験している場面の引用**に限る(全員が実物を知っている場面)。語り手がその場で作った詩的な言い回しは禁止。物理現象は物理の言葉で書く。判定法は「語り手と同じ属性の人が井戸端会議でこれを口に出すか」
- **コピーライターの司会進行を地の文に入れない**。✕「ここで疑問が湧きませんか」「答えは拍子抜けするほど単純でした」「必要な条件は3つでした」「何が違ったのかを書きます」「順番に書きます」。体験談は**起きた順に言うだけ**で運ぶ。メカニズムは**伝聞で3〜5文・要素2つまで**(3つ目以降の理屈はLPの仕事。長く説明するほどその中で発明比喩と司会進行が湧く)
- **複数本は「冒頭差し替え」にしない**。フックだけでなく**発見の経路・感情の山・行動の変化**まで案ごとに別にする。copy-check.mjs の案間重複が30%を超えたら書き直し(悪い版は31〜47%、良い版は16〜22%)
- **記号付き箇条書き(✅ ✔ ■ ▶)を本文に入れない**(運営者 2026-08-17: チェックマーク・図解はAIっぽい)。変化は箇条書きにせず行動の描写で言う
- **人間の文で書く**。AI癖(短文を句点で切りすぎ・改行連打・全文同温度・整いすぎた並列)は不合格。`references/jp-writing-style.md` のヒューマナイズ規則とチェックリストを必ず通す
- **ユーモアを1〜2箇所**入れる。型は先回り自虐(「これから悩むことは、たぶん私が先に全部経験しています」「3年も遠回りしたあとでした」)・自己ツッコミ・余談。笑わせるためではなく「人間が書いてる」証拠として。**ただし日本語として不成立な言い回しは即不合格**(jp-writing-style.mdの自然日本語ゲート)
- **語り手のプロフィールは購入者から逆算**(運営者 2026-08-16)。悩む人ではなく「買う人」の年齢・性別・立場に語り手を一致させ、年齢マーカーを本文か締めに置く。※かつて推奨していた自己ラベリングの捨て台詞は**2026-08-29に撤回**(書かない)
- **語り手は一人称**。語り手が体験者の時は、商品との出会いを**「発見」**として書く(掲示板で知った・調べていて見つけた・勧められた)。メカニズム知識は語り手が「読んだ・言われた」伝聞で入れる(お手本ねぎらい方式)。三人称・「私たち」の広告主文体も禁止。実在人物への紐付け条件は従来どおり
- **主語を落とさない(2026-08-29。最頻の差し戻し)**。「たぶん同じだと思います」では読者が「何が?」で止まり、共感を集める文が単なる推測の文に変わる → 「**あなたも**たぶん、**私と**同じだと思います」。足すのは読者が一瞬でも止まる場所だけ(自明な場所に足すと語順が濁る)
- **です・ます調に、だ調の断片を混ぜない(2026-08-29。差し戻しの根本原因)**。**短くする＝文を途中で切る、ではない**。段落の短さは「1段落あたりの文の数」で作り、**文そのものは主語と述語を揃えて必ず終わらせる**。✕「数秒です。たぶん5秒もありません。」→ ○「我に返って手を下ろすまで、ほんの数秒だったと思います」。体言止めの列挙は**前振りを置いてから**並べる(前振けなしの連打は不合格)
- **専門語と数字はその場で説明する(知識ゼロ前提。2026-08-29)**。数字を出したら何の数字かを言い、専門語を出したら次の1文で必ず言い換える
- **購入遍歴を序数で数えない(2026-08-29)**。「1つ目を買ったのは」では"1つ目の何"かが不明 → 「**最初の◯◯を買ったのは**」「**次に買ったのは**」。**1購入＝1段落で「何を買って／どう作動して／どうダメだったか」まで書く**。総数の辻褄も合わせる
- **失敗の理由は矛盾だけ先に置き、答えは後半まで伏せる(2026-08-29)**。矛盾（やったのに、ここだけ残る）を見せ、原因は言わず「そのときは自分のせいだと思っていました」のように閉じる。ここで答えを言うとメカニズム章が不要になる
- **枠を先に置いてから中身を出す(2026-08-29)**。中身を先に書いて後から枠を言わない。「**〜な◯◯があります。**」と枠を先に置き、次の文で「それは〜することです」と中身を出す
- **フックと本文に論理矛盾を作らない(2026-08-29)**。「気づかなかった」と「毎朝それをするのが習慣だった」は両立しない。**知らなかった対象をずらす**(事実は知っていた／知らなかったのは"その事実の意味")
- **「笑」をバカバカしいところに1〜2箇所(2026-08-29)**。「掃除機で吸ったのは2回です笑」「前髪を切りました笑」。**落差で効かせる箇所には入れない**(自分でオチを説明したことになる)
- **締めは 変化→オファー→納得→打消し→P.S.→P.P.S.(2026-08-29確定)**。オファーは「今ちょうど30日間の返金保証がついていて、セールもやっているみたいです。私と同じことで悩んでいる方は、一回買ってみてもいいんじゃないかなと思います。私にとっては、ここ最近でいちばんのベストバイでした」型。**納得は中盤で放り出した症状の回収に使う**(商品の話に移った感じが消える)。複数本作るなら納得の中身を人格ごとに変える
- **クローズのフック回帰と自己ラベリングの捨て台詞は書かない(2026-08-29で運営者が撤回)**。「さっきのテストです。明日の朝〜」「以上、◯◯な40代おばさんの長話でした」は両方とも不要
- **脅しで買わせない**。責める向きを読者ではなく過去の自分に向ける
- **P.S.とP.P.S.は必須で、どちらも短く**(運営者 2026-08-16)。P.S.=2文前後: 「外観だけ似せた模倣品がAmazonなどに出ているそうです。◯◯(UMの一言)がそろっているのが本物。公式ページからどうぞ。」— 伝聞形「〜そうです」で書く。P.P.S.=3〜4文: 読者の今の思考を言い当てる→「私もそうでした」→カスタマー目線で保証に触れて「一旦、試してみてください」→**必ず「私はそれで◯◯(行動事実)なので、皆さんもそれで解決したら嬉しいです」の祈りで締める**(運営者 2026-08-16: どのパターンでも最後はこれ。売る側の押しではなく、うまくいった客のおすそ分けとして終わる)
- **売り手の口ぶりを排除(絶対)**。「だからこその返金保証です」「〜を用意しています」「期間を長めにしました」のような、オファー・保証を自分が設計した口ぶりは1つでもあれば売り手バレ=広告に見える(運営者 2026-08-16)。語り手はカスタマーとして保証を**見つけた・恩恵を受けた事実**として語る: 「返金保証があったから、私も安心して買えたクチです」「どうせ返金保証もついていますし」。grep検査: 「だからこその」「用意しています」「にしました」(オファー文脈)
- **ヘッドラインは本文と別枠で管理**し、**その案が刺したいペインをそのまま名指しする**(2026-08-30 運営者指示で改訂。「◯◯に悩んでいる人へ」型)。現象で絞る旧ルールは撤回 — 絞りすぎて分かりにくい。案ごとに層が違うので5案なら5通りのペインを書く。**遠回しにせず短く**
- **「次どうなる?」で引っ張る構成**。体験記は時系列で進める(発症→迷走→諦め→転機→発見→変化)。解説型の進行(問題→説明→商品)は引力が弱い。段落の終わりはできるだけ「次を読まないと落ち着かない」文にする(references/copy-structure.mdの読ませる進行)。開幕は体感テスト型が最強だが縛られない — 複数パターンを使い分ける
- **当事者しか使わないワードを本文に1〜2回**必ず入れる(採集語彙から選ぶ)。品質ゲートのチェック項目
- **解決側UMを必ず立てる**。問題の命名だけでは半分。「なぜこの商品じゃないといけないか」を競合が言えない形で言う。立たないなら納品物冒頭で警告
- **実際には付かない特典・付属品を、付くように書かない**。冊子・おまけ・サポートなど、買った人の手元に届かない物を「付いてきました」「プレゼント」と見せない（運営者 2026-08-16「監修小冊子が付いてきました」は嘘。2026-10-20 に言い方を絞った）。話の中の権威や数字の扱いは縛らない
- **商品は遅出し**。本文の前半は問題の再定義(問題に固有名を付ける)とメカニズムに使い、商品名は55〜65%地点まで出さない。冒頭に商品=広告と即判定され死ぬ
- **語彙採集を飛ばさない**。AIは食わせたものの質までしか出せない。語彙・実例・診断のどれかを抜くと定型広告文になる
- **売るのを忘れない**。native staticは低CPC/高CTR/低CVRが正常(トラフィックの割引)だが、curiosityでCTRだけ稼いで商品への橋が無いコピーは罠。品質ゲートで「最終的に売っているか」を問う(references/copy-structure.mdの経済構造)
