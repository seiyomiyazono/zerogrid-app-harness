# カゴ落ちメール4通の審査の決まり

読む人: 4通を審査する編集長（書いた本人でない Claude）。`scripts/審査を回す.py` が下の「## 審査の決まり」を渡す。
読む時: 審査の回ごとに全部。
読まなくていい条件: 4通以外（記事・店・広告）の審査。

## 審査の決まり

4通（と前に買った客の枝 e3b・e4b）を、参考4本と `SKILL.md` の関門で照らす。毎回、全部の段を上から順に見て、ずれを全部書く。前の回に○だった所も見直す。

| 照らす物 | 照らし方 | FAIL にする時 |
|---|---|---|
| 段の並びと形 | `shots/<通>_390.png`・`_600.png` を、`dist/ref/` の同じ通の参考画像と段ごとに並べて見る。段の名前は `SKILL.md` の「4通の段」 | 参考にある段が無い・形（帯・面・カード・ボタンの形）が違う。外してよい段は「4通の段」の表で「外してよい」と書いた物だけ |
| 読み手に起こす効果 | 段ごとに、参考がその段で読み手に起こしている効果（`references/見本4通.md` の「読み手に起こす効果」）が、日本語の文でも同じに起きるか | 直訳で命令・道案内・売り込みに読める。効果が別の物になっている |
| 店の事実 | 値段・保証の日数と条件・評価と件数・送料・問い合わせ先・署名の人を、`店の値.json` の `check.facts` に書いた店の表示の写し（ファイル）と照らす | 店の表示に無い事・食い違う数字。保証の条件が店のポリシーと違う（例: 手数料があるのに「全額」） |
| 割引と期限 | 割引は3通目と4通目の初めての客の枝だけ。4通目の期限は、送る仕組みがカゴごとに作るコードの本当の期限だけ | 1・2通目か e3b・e4b に割引がある。期限の無いコードに期限を書いている（偽の締切） |
| 権威の段（2通目） | 専門家のカードが、店と記事に出ている人（`店の専門家.tsv`）だけで、写真と本文が出どころと同じか（K5）。推薦の一言が本文の言い換えか | 出ていない人がいる。写真か本文が出どころと違う。推薦の一言に言えない言葉か効果の言い切りがある |
| 声 | 名前と本文が店の表示と一字一句同じか（`最終確認.md` の K5）。太字の一言は本文の言い換えで、同じ言葉を2回読ませない | K5 が ×。太字の一言が本文と同じ言葉の繰り返し |
| 写真 | 段ごとに、参考の同じ段の写真の役（使った後の場面・商品・声の人の場面）と同じ役か | 役が違う写真。商品と違う物が写っている |
| Liquid | `liquid/<通>.liquid` に、カートの戻り先 `abandoned_checkout.url`・配信停止 `unsubscribe_url`・カートの中身の繰り返しがあり、見本の値（見本の名前・見本のコード）が残っていない | 見本の値が残っている。配信停止が無い |
| 機械の検査 | `最終確認.md` の K1〜K5 が全部○で、指紋が今の物と同じ | 1つでも × |

## 答え方

メールの物は1つも書き換えない。読んで照らすだけ。最後に次の JSON を1つだけ書く:
`{"decision": "PASS" か "FAIL", "reasons": ["指摘1件を1文で。どの通・どの段・何がどう違うか・何に合わせるか", ...]}`
reasons には直す所だけを書く。合っていた所・良かった所は書かない（書くと指摘として数えられ、出し直しになる。2026-10-20 ここちドライ4回目）。PASS で reasons が空: 直す所が無い。PASS で reasons あり: 合格だが書き方だけ直す所がある。
