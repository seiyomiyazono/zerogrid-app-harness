# listicle-copy — リスティクル（ネイティブ広告のフォーマット）を写して1本作る

読む人: リスティクルを1本作る Claude。
読む時: 作る前に毎回、全部。
読まなくていい条件: 文言を1か所だけ直す時（その記事の移植表を開いて直し、手順6の検査から入る）。

題で数を言い（7つの得／7つの理由）、理由を番号で1つずつ積み、理由の1つで今ある解決策（安い同種の物・薬・手術）を数字つきで名指しで切り、数の証拠（% か大きい数字3〜4個）→商品の紹介（成分か使い方）→客の声→割引と残り時間つきの値段→90日の保証で申込へ送る記事を作る。型の正本は `ec-ad-ops/references/article/型の資料/runs/listicle-native/型.md`。段の作り方のブロックの詳細は `ec-ad-ops/references/article/02-記事（アドバトリアル）/型_リスティクル.md`。骨組みは `bakuro-copy` と同じ（手順・検査・審査は同じ道具）。

このファイルの並び順は意図的。冒頭＝外せない関門、中盤＝参考（引く物）、末尾＝実行手順。

## 合格の定義

# 3. 実行手順（毎回この順）

0. **型と段階を確かめる**: `ec-ad-ops/references/article/型/_VSLから型を選ぶ.md` で、受ける広告の Awareness level を最初の3行から決める（Solution Aware＝今ある解決策の名前を出して切る／Problem Aware＝症状の名前から入る）。広告の組み立てが S（切る物→違いの名前）か A（本人の長い物語）かを `広告と型のつながり.md` で確かめる。違えばそこに書いた型へ
1. **参考を開く**: 上の「参考（1本に固定）」の Metabolae。広告の本文の最後の3行を書き出す（記事が受ける物＝切った物の名前と「違いは◯◯」）
2. **移植表**: 参考は記事の参考だけを使う（VSL の場面・絵は持ちこまない。C5）。頭に「オファーの表」（値段・セット・保証・送料・評価の数。本番の店があれば `products.json` と商品ページから、テストの商品は決めた値）と「1 の言い方」の欄（`_必ず入れる物.md`。書き手は 編集部・記者／体験した本人／専門家 のどれかで、参考の書き手と同じ立場。リスティクルは編集部の語りが多い）。その下に「色」の行（記事から店へ移った人に、別の店に見えないようにするため、色は飛び先の店から取る）: `curl -sL <店の商品ページ> > 店.html` の後、`grep -oiE '#[0-9a-f]{6}' 店.html | tr A-F a-f | sort | uniq -c | sort -rn` で色の一覧を出し、色ごとに `grep -oiE '[^{}]{0,60}\{[^}]*<色>[^}]*\}' 店.html | head -3` でその色を使う部品を見て、ボタンの地・濃い色（帯か枠）・薄い地（段の背景）・見出しの字の4色を、部品の名前つきで書く。出た数では選ばず、選ばれた行の印や札のように部品1つだけの色は取らない。店が無い商品は `決めた値.md` の色。この文書の「テーマの色」「商品の色」「色はブランド」はこの4色を指し、`値段の段を組む.py` の入力の色は 主＝ボタンの地・濃い＝濃い色・淡い＝薄い地・枠＝濃い色、ボタンの色＝ボタンの地 を入れる。本文の字の色は advertorial-08 のまま。続けて参考の段を上から全部、段ごとに 型の段・仕事・心理・ビジュアル（参考の `画面_390.png` と `段.md` を見て書く）・コピー、右にうちの日本語と出どころ。写すのは 段の並び・理由の数・見出しの形（番号＋良い事＋本当の理由）・数字の数・画像の置き方。言い回しは直訳で同じ効果が起きるなら直訳。商品が参考（サプリ・茶）と違う種類（道具・サポーター）なら、「効くまでの時間」「数値が下がる」の理由は「治す物ではなく、痛む体のまま暮らしを小さくしない物（朝の一歩・立ち仕事・寝る時）」に置き換えてから訳す（原因の段と食い違う約束を作らない）。申込の先の段も同じ表に続けて書く
3. **必ず入れる物を足す**: 最悪の結末は題の下の箱（参考の題の下の帯と同じ形。理由1の見出しは最悪の結末を避ける理由にする）、値段の見せ方は値段・オファーの段と申込の先。枠に `data-tasu`。**最初の画面は字を少なく**: 題は36字以内（幅390で3行以内。英語の題を直訳して長くしない。数と「本当の理由」だけ残す）・導入は50字以内・最悪の結末の箱は90字以内（3行。原因→起きる事→最悪→最後まで読んでほしい、を各1文）。確かめは `幅の検査.py` の390の最初の画面と、題と箱の字数
4. **組む**: 移植表どおりに `index.html` と `申込/index.html`。段ごとの枠に `data-dan="<型の段の番号>"`、申込のボタンに `data-cta`、`<meta name="robots" content="noindex">`。字の形はうちの店の商品ページと同じ（Zen Maru Gothic・見出し 800〜900・本文 400〜500）、段の並び・部品の数と置き場は参考、部品の見た目（ボタン・数字・引用・書き手の欄・値段・保証・締め）はここちドライの記事 advertorial-08 の形（最後の確かめの D3・D4b）。文は BudouX（`_env/venv/bin/python -c "import budoux"`）で文節に割って切れ目に `<wbr>` を入れ（文末まで3字以下の所には入れない）、`word-break: keep-all`。文の中の値段・数の箱の字の色は、親の箱の色を引き継がせず箱ごとに書く。申込のボタンの行き先は全部 `申込/index.html`。画像だけを入れる入れ物は `<div>`（`<p>` にすると `画像の置き方.py` が画像に数える）。`loading="lazy"` は付けない（審査の画面取りで空白になる）。ボタンは advertorial-08 の `a.cta` の形1種類で、置き場は参考の記事と同じ。数合わせの空の部品は置かず、合わない数は最終確認 D4b・D8 に理由を書く。**ボタンの文は読み手の望む結果**（「もう、[痛みの場面]しない毎日へ ›」の形。動作の文にしない）。値段の段は `値段の段を組む.py` の断片（ここちドライの形）。申込の先は参考の商品ページの順（セットの箱・いちばん大きいセットを選んだ状態と「一番人気」・保証・タイマー・申込のボタン）。最後のボタンは押すと「ここで送信（テストのため止めています）」の帯を出すだけ。分からない所は予測して作り、`予測した事.md`（何を・どう・根拠）とテスト用の値は `決めた値.md`
